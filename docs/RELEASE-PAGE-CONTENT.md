## 3. 自签名说明（请先读）

本安装包**使用项目自签名证书**（2026-11-09 实测 `Get-AuthenticodeSignature` = `Valid`，
主体 `CN=鎏灏智能中枢, O=LiuHao AI OS, C=CN`，SHA-1 指纹以 `AE398F09` 开头），
**不是公开权威 CA 签发**。这不是病毒提示：

- 双击安装包时，Windows 可能弹出「Windows 已保护你的电脑」或「未知发布者」——这是自签名证书的正常现象；
- 从网盘、U 盘或聊天工具转存后打开，也可能出现同样提示；
- 未导入信任的机器上 `Status` 可能显示 `UnknownError`（根证书不受信任），运行随包「信任签名证书.cmd」后应为 `Valid`；
- 签名有效不代表来源可信：请务必核对本页的 SHA256。

SmartScreen 绕过步骤（Windows 10 / 11 相同）：

1. 看到「Windows 已保护你的电脑」蓝色窗口时，点左侧的**「更多信息」**；
2. 窗口下方会出现「应用：`LiuHao-Setup-<版本号>.exe`」和**「仍要运行」**按钮，点它；
3. 若弹出 UAC（只在回退安装到 `C:\Program Files` 时才会出现），点「是」；
4. 进入安装向导后按提示操作；默认安装路径不需要管理员权限，也不会弹 UAC。

如果点「更多信息」后没有「仍要运行」，或提示「已被组织阻止」：
说明文件可能被改动或来源不可信，请停止安装，重新从本页下载并核对 SHA256。

包已做项目自签名；若后续改用公开 CA 签名，文件字节与 SHA256 会变，
届时请以新发布页给出的值为准，旧校验值自然失效。

## 4. 安装位置、权限与数据

默认**程序与数据分离**：

| 项目 | 默认位置 |
| --- | --- |
| 程序 | `D:\LiuHao` |
| 用户数据 | `D:\LiuHaoData`（不在程序目录内） |
| 权限 | 默认**不需要管理员权限**，不弹 UAC |

D 盘不可用（不存在 / 不可写 / 是可移动盘）时：

- 程序目录自动回退到 `%LOCALAPPDATA%\Programs\LiuHao`（当前用户目录，不需要管理员）；
  如果以管理员身份运行，程序回退目标为 `C:\Program Files\LiuHao`。
- 数据目录：安装向导会停下来让你确认/改选，D 盘不可用时通常预填 `%LOCALAPPDATA%\LiuHao\data`；
  没有检测到可用非系统盘时，数据目录和备份目录都自动落到 `%LOCALAPPDATA%\LiuHao`，
  安装继续、不会中断，向导会提示「没有检测到非系统盘，数据与备份都在 C 盘，建议预留空间」。
  也可以改选非系统盘目录（例如 `E:\LiuHaoData`）。
- 备份根默认按数据目录所在盘推导；没有可用非系统盘时随数据目录一起落到
  `%LOCALAPPDATA%\LiuHao`。命令行安装可用 `/BACKUPS=<目录>` 指定。

回退时安装向导的「准备安装」页会写明实际位置与原因，程序目录里也会留一份
`安装位置说明.txt`。已经装在 C 盘的老用户，覆盖安装/升级保持原路径不变。

**卸载默认保留数据**：卸载时会问一次「是否同时删除数据」，默认「否」；
只有连续两次确认才会永久删除数据目录。覆盖安装（升级）不会碰数据目录。

备份方法：退出鎏灏后，把整个数据目录复制到移动硬盘或另一台电脑。
必须同时复制 `data\model_config.key` 与 `data\model_registry.sqlite3`；
少一个，已保存的 API Key 就解不开（Key 用 AES-256-GCM 加密，只存在本机）。

## 5. 联网与隐私（默认不联网）

**默认不主动联网。** 只有你自己做了以下配置后才会产生传输：

- 配置云端模型：对话内容与为回答而检索到的知识库片段会发给该模型服务商；
- 部署时显式设置云端向量化（`LIUHAO_EMBEDDING_PROVIDER` + 凭据/地址；界面不提供该开关）：知识库入库文本会发给该向量化服务商；
- 在「设置 → 隐私与联网」显式开启「联网检索」（默认关闭）：
  只发送提炼后的检索关键词（最多 48 个字符，先去掉邮箱、电话、密钥和链接），
  目标固定为 `hn.algolia.com`、`api.github.com`、`export.arxiv.org`；
  不发送对话内容、历史、个人画像、账号信息或 API Key。

不会发到模型服务商：API Key、账号密码、审计记录、本机对话/知识数据库文件。
本机 Ollama 模式只连 `127.0.0.1:11434`，不出本机。

不收集使用统计、不做遥测上报；未配置更新源时不会主动检查更新。
运维类功能（漏洞情报、升级清单、RFC3161 时间戳、告警 Webhook、第三方集成、
MCP Server）默认全部关闭，需要显式配置或主动连接才会访问对应域名。

加密边界：只有 API Key 加密；对话、知识库、审计是本地明文 SQLite 文件，
依靠 Windows 账号权限保护。多人共用或设备可能丢失时，建议开启 BitLocker。
多个 Windows 账户共用同一台电脑时，数据与密钥不按用户隔离。

## 6. 安装包里有什么、没有什么

- **不含任何 AI 模型**：不带 Ollama、GGUF 或模型权重，安装包因此较小；
- **不含任何密钥**：构建时已剔除 `auth_secrets.json`、`human_identities.json`、
  外部锚私钥与容器环境配置；账号与密钥在你自己机器上首次生成；
- **包含第三方许可证**：安装目录有 `THIRD-PARTY-NOTICES.txt` 与 `licenses\`；
  登录后也可在「关于与隐私」查看。

首次启动向导给三种模型选择：本机 Ollama、OpenAI 兼容云、或先跳过。
没有 API Key 也能先安装、先启动，之后在「系统设置 → 模型管理」补上，无需重装。

## 7. 出问题先导诊断包

安装或启动异常时，**先导出诊断包再反馈**：
开始菜单 →「LiuHao AI OS · 鎏灏智能中枢」→「收集诊断信息（离线）」，
双击即可在桌面生成脱敏诊断包（服务未启动也能用），把该文件发给我们。

排查顺序（可选）：先看托盘是否在、再试「停止服务」后重开；
需要命令行输出时，在程序目录运行 `LiuHao.bat --console`。
控制台默认地址 `http://127.0.0.1:8080`；**首启向导里可以换端口；日常启动如果端口被占，
会告诉你占用原因并给出处理办法**（关掉占用程序再试，或改端口后重新启动）。

## 7.1 升级：覆盖安装后必须重启

- 需要换版本时，直接用本页的安装包覆盖安装；安装完成后**请退出并重新启动鎏灏，新版本才生效**。
- **运行中升级当前不可用**（实测）：运行中的服务会以 409 拒绝安装请求；即使强行替换文件，
  自检也可能被前端兜底页误判为通过；失败回滚可能留下新旧混合的程序目录；升级完成后
  也不会自动重启。因此不要把「点一下就自动完成升级」当作可用能力。
- 覆盖安装不会删除数据目录；程序目录里旧版遗留、新版已排除的文件，按安装器的清理规则处理。
  **但 0.1.1 → 0.1.2 这一步不会清理 0.1.1 曾随包发出的内部文档**：这批文档要等从 0.1.2
  升到下一版、且走应用内升级时，才按精确清单（路径 + SHA256）清理；清单外的文件、
  用户自建或改过的文件一律不动。
- 升级包（ZIP）只用于开发/运维验证，不面向普通用户分发。

## 8. 交付目录与归档语义

**唯一可发布目录**：`dist\installer\` 顶层（exe、`liuhao-<版本>-upgrade.zip`、`SHA256SUMS.txt`、`README-DELIVERY.txt`；0.1.2 起还有 `FREEZE-RECORD.json`）。

- `dist\_archive\**`：历史追溯，**不得分发、不得作为页面数值来源**；归档目录的 `README.txt` 写明原位置与原因。
- 其他 `dist\<快照名>\installer\**`：历史构建快照，同样不得作为交付依据。
- 判定「哪个是线上包」只认发布页 SHA256 与 `dist\installer\SHA256SUMS.txt`，**不认**目录名、时间戳或文件大小。

已归档实例（0.1.1 同名不同文件）：

| 目录 | 字节 | SHA256 前缀/后缀 |
| --- | --- | --- |
| `dist\installer\`（线上口径） | 29,567,136 | `49BC50C8…B4DF` |
| `dist\_archive\brand-verify-installer\` | 35,089,104 | `222160D4…DDD9` |
| `dist\encpath\installer\` | 37,856,638 | `172363C9…935C` |
| `dist\installer\_archive\20261107-mixed-0.1.0-and-0.1.1\` | 34,830,483 | `0BF400D6…BF45` |

> 2026-11-09 实测：`dist` 下共 16 个 `LiuHao-Setup-*.exe` 快照，其中 4 个是 0.1.1（上表），
> 其余 12 个是 0.1.0。完整清单（含字节与 SHA256 前后缀）见 `docs-gap-sweep` 证据 `dist-snapshot-inventory.txt`。
> `dist\encpath` 与 `dist\installer\_archive\...` 尚未移入 `dist\_archive\`，建议发布主线一并归档。

## 9. 换版核对（发布页手写值，无自动生成）

线上发布页 HTML 不在本仓库（独立 GitHub Pages 仓库），页面里的版本、哈希、字节全部手写，没有构建注入。2026-11-09 对线上页面实测，可机检的手写值共 **25 处**：

| 类别 | 处数 | 说明 |
| --- | --- | --- |
| 版本号 `0.1.1` | **15** | meta description、版本徽章、下载卡、FAQ、命令示例（第 482 行有 2 处） |
| 完整 SHA256 | **4** | 同一个值重复：下载卡 ×2、校验区 ×2 |
| 体积表述 | **6** | `29,567,136 字节` ×2、裸 `29567136` ×1、`28.20 MB` ×3（第 388/404/487 行） |

> 「23 处」的口径差异：需求方记的是「版本 15 + 哈希 4 + 字节 4」；实测脚本按文本出现次数扫描为 25
> （体积 6 处）。差异来自 `28.20 MB` 实际出现 3 次、且「字节 4」把近似值按 1 类去重了。
> 核对时以脚本扫描结果为准，不以任一人工口径为准。
> 另外 `28.20 MB` 实际是 **MiB**（29,567,136 / 1024² = 28.197）；按十进制应为 29.57 MB，页面单位标注有误。

最容易漏的三类，换版时逐处核对：

1. **下载按钮 `href` 文件名**（`LiuHao-Setup-<版本>.exe`）：改名后忘改 href，按钮直接 404；
2. **`data-copy` 属性**：复制按钮里存的是旧哈希 / 旧文件名，页面显示对了但复制出去是错的；
3. **裸字节数**：页面同时出现 `29,567,136`（千分位）与 `29567136`（裸写），只改一种会自相矛盾。

可复用核对脚本（本补丁新增）：

```powershell
python scripts\verify_release_page_values.py --page <index.html> --record <FREEZE-RECORD.json>
```

它会检查：所有版本号一致；所有 64 位 SHA256 等于记录值；所有 `LiuHao-Setup-*.exe` 文件名版本一致；
`data-copy` 只允许记录中的哈希 / 文件名；所有千分位与裸字节数等于记录 `installer.size`；
近似体积与 `size/1024²` 相差 ≤0.05。退出码 `0`=通过，`1`=有差异，`2`=参数或文件错误。
