## 0. 一句话结论

保存/测试/更新/运行时四条路径都已落地同一套目标校验：非 http(s) 400、现填地址解析出私网/回环/链路本地/保留/多播 400、带 Key 走 http 400、跨域重定向与探测期 DNS 漂移 400；放行面只收窄到「回环 + provider=ollama 或已知本地推理端口（11434/1234/8000/8080）」与「已知本机 Ollama 地址」。**可以带缺口发布**：DNS 重绑定只有代码级防护证据（线程钉住解析），无真实 DNS 层实测；Ollama 例外对回环端口不做限定属已登记的残余风险。

## 2. 四问逐条回答

### 问① DNS 重绑定是否被拦
**真实 DNS 层未测**（硬约束不允许改系统 DNS，本机也无可控权威解析器），现有证据是代码级：
- 每次**真实请求前**重新解析并校验，校验通过的解析结果**按线程钉住**，SDK 建连时 `socket.getaddrinfo` 只拿到已校验地址，消掉「校验时公网、建连时私网」的 TOCTOU 窗口：`src/ai/net_guard.py:131-180`（`_pinned_getaddrinfo`/`_pin_resolution`）、`:199-205`、`:240-270`。
- 「测试连接」预检禁跟随重定向（跨域 3xx → 400）并**二次比对解析结果**，变化即 400「疑似 DNS rebinding，已拒绝」：`src/gateway/models.py:955-1009`（含已声明的局限：不钉 SDK 自己的 socket，特定请求后才重定向的服务器探不到，models.py:962-965）。
- 结论：**机制在，实测缺真实 DNS 层一环**。登记口径照写「真实 DNS 层未测；现有证据是 net_guard 钉住解析器的单元级证据（known-gaps 4.1）」，不得写成「已验证防住」。

### 问② 「已保存放行」边界是否覆盖所有调用路径
- 运行时守卫 `assert_safe_runtime_target` 在每类 provider 的每次真实请求前调用，调用点枚举：OpenAI 兼容客户端 `src/ai/providers.py:2292-2294`、Anthropic `:2645`、Google 自定义端点 `:2746`、Ollama 生成/流式/embedding `:2796-2800`、`:2927-2931`、`:2863-2867`（这三处是唯一 `allow_private_service=True` + `allow_loopback=True`）、Moonshot `:3005`、DeepSeek `:3112`；「发现模型」`src/ai/model_discovery.py:160-164`（`is_ollama` 时才放宽）。聊天、目标拆解、embedding 均经 provider 层，故共享同一守卫。
- 且放宽再被收窄一层：即使 `allow_private_service=True`，`skip_private = allow_private_service and is_local_ollama(value)`（`net_guard.py:238`）——只有命中已知本机 Ollama 地址集（127.0.0.1:11434、localhost:11434、`OLLAMA_BASE_URL`）才放私网，普通局域网地址运行时仍拒。
- 保存侧再校验收紧确认：已保存配置重验时「仅对本机 Ollama 保留私网/回环放行；其他私网地址重新收紧」`src/gateway/models.py:1283-1289`；测试路径换目标必须重输 Key（409 MODEL_KEY_TARGET_CHANGED）`models.py:1222-1243`。
- 口径修正（如实）：§7.2 写的「已保存配置放行私网（allow_private=True）」实际范围比字面窄——`_validate_base_url` 的 `allow_private` 仅在 `provider=ollama 且地址命中本机 Ollama 集` 时为真（`models.py:359-363`）；其 `stored_url` 参数（`:319`）在函数体内**未被使用**，`_assert_url_allowed` 文档串里「与已保存配置逐字相同即放行」的表述（`:1142-1144`）与代码不完全一致，实际行为是更严的「仅本机 Ollama」。行为无害（更严），但文档措辞应在下次触碰该文件时对齐。

### 问③ 允许/拒绝清单要不要写死到配置
不需要新增配置面。现行白名单是**代码级常量**（本地推理端口 `net_guard.py:48`、危险标志位 `:38-45`、本机 Ollama 集 `models.py:285-312`），好处是不可被运行时配置静默放大；唯一可配置入口是 `OLLAMA_BASE_URL` 环境变量（运营者自配的局域网 Ollama，`models.py:286-298`、`net_guard.py:58-68`），且仅对 ollama provider 生效。建议维持现状并在交付说明披露白名单内容；若未来要支持用户自定义白名单，必须走「落盘 + 审计 + 仅 root」而不是普通设置项。

### 问④ 本机 Ollama 例外是否应限定为 127.0.0.1/localhost 字面量
**不应只限定字面量，且现状已比字面量口径更精确**：
- `localhost` 字面量本身不是通行证：`http://localhost:9999/v1`（provider=openai）被拒，错误体显示 `localhost -> ::1`（实测 B2=400）。判定按**解析后地址**做（`net_guard.py:86-119`），localhost 与 127.0.0.1、::1 同走回环规则。
- 回环放行的真实条件是「回环主机 +（provider=ollama 或 命中白名单推理端口）」（`models.py:362`、`net_guard.py:122-128`）；provider=ollama 时不限端口（Ollama 可监听 11435 等自定义端口，`models.py:347-349`）——这是设计决定，实测 C1（127.0.0.1:19099，provider=ollama）=200 佐证。
- 残余风险（如实登记）：provider=ollama + 任意回环端口意味着把配置类型改成 ollama 就可指向回环上的任意端口（如 127.0.0.1:2375 Docker API）；缓解因素是仅回环（到不了内网）、需模型管理员身份才能保存、调用仅限模型链路。若要进一步收紧，可对 ollama 类型加「非白名单回环端口需显式确认」，属后续加固项，不阻塞发布。

## 4. 「已防护但风险未消除」口径

已防护（有代码 + 本轮实测）：scheme 白名单、私网/回环/链路本地/保留/多播解析拒绝、带 Key 必须 https、跨域重定向拒绝、运行时逐请求重校验、探测期解析漂移拒绝、Key 不随目标变更复用。
未消除（诚实披露）：① DNS 重绑定无真实 DNS 层实测，只有「校验后线程钉住解析」的代码级证据（且探测面自认不钉 SDK socket 的局限，models.py:962-965）；② ollama 类型的回环例外不限端口，回环管理面端口依赖「仅回环 + 管理员权限」两道软约束；③ 白名单为代码常量，未来扩端口需改代码发版。

### 发布披露文案建议（可直接引用）

> 自定义模型接入地址已内置 SSRF 校验：仅接受 http/https，解析到私网、回环、链路本地或保留段的地址一律拒绝，带密钥的地址必须使用 https；本机 Ollama 与常见本地推理端口按白名单放行。DNS 重绑定防护已在线程级固定解析结果，但我们尚未在真实 DNS 环境做端到端重绑定实测，该残余风险已登记（known-gaps 4.1）；将模型类型设为 Ollama 时允许指向本机任意端口，请仅对可信的本机服务使用。
