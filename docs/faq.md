# Jarvis · 贾维斯 常见问题（Windows 安装版）

> 本页描述 **0.1.1 及以上版本**的真实行为；旧版本行为不同，请先升级。
> 面向普通用户。短句、按步骤做。
> 文中标 **待确认** 的地方，表示当前仓库里没有已验证的实现或定稿方案，发布前需要人工确认；没有写成“已支持”。

## 1. 填完 API Key，为什么不生效

按这个顺序排查，通常 1～2 分钟能定位。

### 1.1 先确认“保存”和“默认模型”

1. 到 **系统设置 → 模型管理**，确认模型已经保存（会出现在“已配置的模型”列表里）。
2. 确认这个模型被 **设为默认**。
3. 回到自由对话，重新发一条消息。模型配置在下一次请求生效，不需要重启程序。
4. 回到「总览」，看“模型服务商连通状态”：确认当前生效的是你刚配置的那家服务商；
   如果还是 `mock`，说明默认模型没切过去。

### 1.2 点“测试连接”

测试连接成功，说明 Key 和地址基本可用；测试失败，按错误码处理（见第 2 节）。

### 1.3 检查最常见的四个填写问题

| 检查项 | 正确做法 |
| --- | --- |
| `base_url` 少了 `/v1` | 多数 OpenAI 兼容服务要写到 `https://.../v1`；以服务商文档为准 |
| 模型名填错 | 必须和服务商控制台里的模型 ID 一字不差，大小写、日期后缀都要对 |
| Key 不完整 | 重新复制完整 Key，去掉前后的空格和换行；模型管理列表只显示掩码，不会回显完整 Key |
| Key 没有模型权限 | 到服务商控制台确认这个 Key 能调用这个模型，或换一个有权限的 Key |

### 1.4 Ollama 本地模型

1. 确认 Ollama 正在运行（托盘有 Ollama 图标，或浏览器能打开 `http://127.0.0.1:11434`）。
2. 确认模型已经拉下来：`ollama list` 能看到对应模型。
3. 模型名要填 Ollama 里的名字，例如 `qwen2.5:7b`，不要填服务商的商品名。
4. 本地 LM Studio 这类服务，**测试连接可能被安全策略拒绝**，但聊天仍可用；以实际发一条消息为准。

### 1.5 还是不行

- 看回复里的错误码，对照第 2 节。
- 看日志：`<数据目录>\logs\liuhao.log`（服务）与 `<数据目录>\logs\launcher.log`（启动器与向导）。
  数据目录默认 `D:\LiuHaoData`；没有检测到可用非系统盘时，数据目录和备份目录都自动落到 `%LOCALAPPDATA%\LiuHao`（安装继续、不会中断，向导会提示「没有检测到非系统盘，数据与备份都在 C 盘，建议预留空间」）。实际位置见程序目录 `data-dir.txt`。
- 导出诊断包：能打开界面时，**系统设置 → 遇到问题 → 一键诊断包 → 导出诊断包**，把生成的 zip 发给支持。
  包内不含密钥，路径中的用户名已隐去。
- 发问题求助时，只发错误码、日志片段和诊断包，**不要发完整 API Key**。

## 2. 401、404、503 分别是什么意思

这三个是 HTTP 状态码。放在贾维斯里，常见含义如下。

| 状态码 | HTTP 本意 | 在贾维斯里通常表示 | 你要做什么 |
| --- | --- | --- | --- |
| `401 Unauthorized` | 身份没通过 | API Key 无效、过期、复制不完整，或没有权限。登录页则通常是账号或密码不对 | 重新填 Key 或重新登录；确认 Key 没有多余空格；确认 Key 有模型权限 |
| `402 Payment Required` | 需要付费 / 额度不够 | **预算或额度不足**：本次调用会超出可用预算（按保守 token 估算）（`code=budget_exceeded`）。和权限无关 | 到「我的 Key → 用量」调整额度，或换一个更便宜的模型 |
| `403 Forbidden` | 身份通过了，但没权限 | 两种情况：① Key 没有调用该模型的权限（厂商侧）；② 账号没有这项操作权限（`code=permission_denied`，贾维斯本地侧）。界面可能和 401 合并显示为“API Key 无效或没有权限” | ① 到服务商控制台开通权限；② 换用有权限的账号，或让上级账号授权；账号问题找管理员 |
| `404 Not Found` | 地址或资源不存在 | 模型名不存在，或这个端点不支持该模型；也可能是 `base_url` 写错、少了 `/v1` | 核对模型 ID；核对 `base_url`；到服务商文档确认端点 |
| `503 Service Unavailable` | 服务不可用 | 模型服务连不上、过载或暂时不可用；Ollama 用户常见于 Ollama 没启动 | 检查网络；确认 Ollama 正在运行；稍后再试或换模型 |

补充两种：

- `429 Too Many Requests`：触发限流。等一会儿再发，或降低频率。
- 知识库返回 `503 未启用`：有三种原因 —— 向量模型未配置、本机 Ollama 未运行或缺少模型、向量模型已就绪但向量库打不开，不是网络坏了。先看知识中心「知识库状态」卡：显示「向量模型已就绪，但向量库不可用」时点「重新检测」，仍失败再查服务端日志，不要再去重配模型。设计要求是未配置时明确返回 `503`、不能伪装可用；当前版本这条链路的真实端到端表现仍是 **待确认**。

## 3. 断网或没有模型时，还能做什么

分三种情况，不要混在一起。

### 3.1 有本地 Ollama，且模型已经拉好，断网

- 对话可以继续用。本地 Ollama 的推理在本机完成，不需要外网。
- 登录、查看历史会话、改设置、管理模型都能用。
- 前提是 Ollama 服务本身正常；Ollama 也需要本机端口可用。
- 「联网检索」默认关闭，关闭时断网不影响对话；若你显式开启，助手会尝试访问
  `hn.algolia.com`、`api.github.com`、`export.arxiv.org`，失败时只是返回
  「未接入实时联网检索」，不影响本地回答。

### 3.2 用云端 API，但断网

- 发消息会失败，通常是连接错误或 `503`。
- 登录、查看已有会话、查看审计、改设置仍然可用，因为这些都在本机。
- 网络恢复后直接再发，不需要重装或重建账号。

### 3.3 完全没有配置真实模型

- 对话页可能显示 `Mock response to: ...`。这是**演示模式的回显，不是模型回答**，不能当成真实结果。
- 目标、工具、员工执行这类需要真实模型的链路，会明确报“默认模型未配置”，不会拿 Mock 结果冒充成功。
- 本地已有的账号、设置、历史记录和模型管理仍然可用；配好真实模型后再聊天。

### 3.4 断网时不能做什么

- 不能调用云端模型。
- 默认配置下不能检查远程更新。升级入口在 **系统设置 → 软件更新**：未配置更新源时「检查更新」按钮禁用并写明原因，不会假装“已是最新”；配置了更新源才能检查/下载/校验/应用。没配置时仍可用安装包覆盖安装（先备份数据目录）。
- 知识库检索要求向量化可用；但不命中不等于没配模型——也可能库里没有相关文档，或相关度低于门槛。原因以知识中心「知识库状态」卡为准：显示「已启用」时 0 命中是检索结果问题，不是配置问题。真实链路是否可用，以实际测试为准（**待确认**）。

## 4. 更新失败，怎么回滚

先记住一句话：**升级前先备份整个数据目录（默认 `D:\LiuHaoData`）；回滚会把程序和数据恢复到升级前，升级后新写的数据会丢失。**

### 4.1 最稳妥的做法：覆盖安装旧版本

适合大多数用户。

1. 升级前，按 [END-USER-GUIDE.md](END-USER-GUIDE.md) 的“数据在哪里、怎么备份”复制整个数据目录（默认 `D:\LiuHaoData`，不是只复制里面的 `data` 子文件夹）。
2. 退出贾维斯。
3. 运行新版本安装包，覆盖安装。
4. 如果新版本起不来或明显异常：退出程序，直接运行**上一版本安装包**覆盖安装。
5. 数据目录默认保留；但新版本已经写入的数据不会自动消失。如果数据也被新版本改坏，先退出程序，再用升级前的完整数据目录备份覆盖恢复。

### 4.2 用升级器升级的，怎么回滚

「系统设置 → 软件更新」只负责检查并安装新版本（未配置更新源时按钮是禁用的），**没有回滚入口**；下面只适用于支持人员用命令行升级器操作的场景。

如果你是通过支持人员用命令行升级器升级的：

1. 先退出贾维斯（托盘菜单“退出”；关掉状态窗口只是隐藏到托盘，不算退出）。
2. 联系支持，说明要回滚到的版本；升级器默认取最近一次成功升级前的备份。
3. 回滚会恢复升级前的数据快照，**升级后新写入的数据会丢失**。
4. 如果提示“没有可回滚的升级记录”或备份缺失：直接运行上一版本安装包覆盖安装。

升级过程中断电、被杀进程，下次启动会识别未完成记录并自动恢复；这是升级器已有的保护。

### 4.3 当前版本的边界

- 升级入口在 **系统设置 → 软件更新** 卡片；未配置更新源时「检查更新」按钮禁用并写明原因。普通用户没有更新源时，请用「退出 → 备份 → 覆盖安装」。
- 命令行升级器（服务支持人员使用）已验证读取发布清单；「检查 → 下载 → 校验 → 应用 → 重启生效 → 回滚」的完整链路只在演练环境跑通过，安装版现场仍需验收。安装完成后必须重启程序，新版本才会接管。
- 已在演练环境（本地假发布源 + 独立进程）跑通完整链路，并验证了包被篡改、下载中断、应用中断电三类故障都会自动回滚且旧版本可用；**安装版上的现场验收仍以实际安装包为准**。
- 不要以为没配置也能自动升级：未配置更新源时「检查更新」按钮是禁用状态，不会自动下载。

## 5. 忘记密码怎么办（0.1.1+）

### 5.1 手里有恢复码

1. 打开登录页，点「忘记密码」。
2. 填恢复码（之前生成并保存的那串，形如 `RC-...`）和新密码（至少 8 位）。
3. 点「重置并进入」。恢复码**用一次即失效**。
4. 登录后建议马上生成新码：左侧导航「恢复码」（仅根账号可见）→ 勾选“我明白轮换后旧恢复码立即失效，需要重新保存。” →「生成新的恢复码」。页面会直接显示新码，可复制或「下载恢复材料（未加密）」。旧码立即失效。
5. 「下载恢复材料（未加密）」下载的是**未加密**的明文文件，按密码保管，不要放在同步盘。

### 5.2 没有恢复码：在本机生成

**首次安装时「贾维斯首次设置」不发恢复码**，从 0.1.0 升级上来、从未生成过恢复码的根账号，
第一次忘记密码就走这条路。

1. 用启动器**自动打开的那个原生窗口**进入登录页（双击快捷方式后弹出的那个）；
   手动在浏览器输入 `http://127.0.0.1:8080` 打开的页面**不算本机证明**，这一步会失败。
2. 点「忘记密码」→「没有恢复码？在本机生成」。
3. 页面会直接显示新恢复码，标题是“新的恢复码只显示这一次，请立刻抄下来，或存进密码管理器。”
   下面就是形如 `RC-...` 的码，旁边有「复制」。抄下来（或点复制），再填新密码（至少 8 位）
   →「重置并进入」。
4. 后台把码写进本机加密交接文件 `<数据目录>\config\recovery_code.txt`（Windows 用当前登录
   用户的凭据加密，不是明文），交给页面一次后**立即删除文件**（用完即焚）。
5. 如果提示“本机恢复流程还需要桌面端的一次性证明…”，说明当前页面不是启动器打开的：
   关掉这个标签页，回到桌面**重新双击快捷方式**，用新打开的页面重试。
   不要反复点“在本机生成”：每点一次都会让上一枚码失效。
6. 如果提示“已存在有效的恢复码；请使用已有的码，或登录后在“恢复码”页重新生成”，
   说明已有可用码；用你保存的那枚，或登录后在「恢复码」页轮换。

### 5.3 恢复码的边界

- 只对**根账号**签发；成员账号由根账号在「成员与权限管理」页处理。
- 只显示一次、只存哈希；界面与日志不会再次显示明文。
- 没有有效期，但**一经使用即失效**；重新生成会让旧码立即作废。
- 不要把恢复码发到群里或写进工单；它等同于账号的最高权限凭据。

### 5.4 如果账号文件和凭据文件都丢了

当前版本没有自动重建入口。按这个顺序处理：

1. 先恢复数据备份；这是最可靠的方式。
2. 没有备份时，不要直接删除数据目录，先联系支持按支持流程处理。

## 6. 浏览器显示旧界面或白屏（0.1.1+）

1. 先确认托盘图标还在、状态窗口显示“运行中”。关掉状态窗口只是隐藏到托盘，网关继续运行。
2. **强刷**：在页面按 `Ctrl + F5`（或 `Ctrl + Shift + R`）。
3. **注销 Service Worker**：按 `F12` → **Application（应用）** → 左侧 **Service Workers** →
   在 `http://127.0.0.1:8080` 那一行点 **Unregister（注销）** → 重新打开地址。
4. **清站点数据**：**Application（应用）** → **Storage（存储）** → **Clear site data（清除站点数据）** → 刷新。
   这会清掉该地址下的登录状态，需要重新登录；账号、Key、聊天记录不受影响。
5. 换过端口时，旧标签页仍指向旧端口；用状态窗口「控制台：」里的新地址重新打开（`current_url.txt` 只是某次启动的快照，可能过期，不要依赖它）。

## 7. 起不来怎么办（0.1.1+）

按这三步做：

1. **看窗口最后几行。** 启动失败时状态窗口会停在错误原因上（双击快捷方式启动的是「Jarvis · 贾维斯」状态窗口；命令行模式 `LiuHao.bat --console` 才是命令行窗口）。
   提示“端口 8080 已被占用”时，程序不会自动换端口：窗口会写清占用原因（占用者 PID / 程序名）
   并给出处理办法——关掉占用程序再试，或在首启向导 / 启动入口换一个空闲端口，不用改快捷方式；
   纯命令行 / 无桌面不会弹窗，而是逐行打印「处理一／处理二」，复制「处理二」下面那条命令（含引号）重跑即可
   （命令里已给出候选端口，通常是 8081），**返回码 2 表示没有启动**。
2. **看两个日志。** `<数据目录>\logs\launcher.log`（启动器与向导）和
   `<数据目录>\logs\liuhao.log`（服务）。数据目录默认 `D:\LiuHaoData`，
   实际位置见程序目录 `data-dir.txt`。先看最后 20～50 行。
3. **导出诊断包。** 能打开界面时：**系统设置 → 遇到问题 → 一键诊断包 → 导出诊断包**。
   看到“已保存：<文件名>”或“已开始下载：<文件名>。请到浏览器的下载位置查看。”，
   就把这个 zip（形如 `liuhao-diagnostics-日期-时间.zip`）发给支持；包内不含密钥，
   路径中的用户名已隐去。打不开界面时，直接发第 2 步的两个日志文件，并附上窗口最后几行。

## 8. 卸载会删掉我的数据吗（0.1.1+）

**程序和数据是分开的，卸载默认保留数据。**

1. 打开 **设置 → 应用 → 已安装的应用**，找到“Jarvis · 贾维斯”，点卸载。
2. 卸载器先删程序，然后问“是否同时删除你的数据？”，**默认是“否”**。
3. 选“否”：账号、Key、聊天记录都还在，以后重装可直接用。
4. 选“是”：还会再确认一次，**两次都确认**才删除 `data-dir.txt` 记录的数据目录
   （默认 `D:\LiuHaoData`），删除后无法恢复。
