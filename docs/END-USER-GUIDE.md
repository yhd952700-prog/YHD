# LiuHao AI OS · 鎏灏智能中枢 使用指南

> 本指南描述 **0.1.1 及以上版本**的真实行为。旧版本在安装位置、端口处理和恢复码上与本指南不同，请先升级再对照操作。
>
> **版本差异（先对号）**：0.1.0 的安装包只有**命令行向导**；0.1.1 起才有图形「鎏灏首次设置」窗口。
> 若你双击后只看到黑窗口逐项提问（`[1/2]` 管理员账号 → `[2/2]` 选模型 `1`/`2`/`0`），说明是 0.1.0：
> 按黑窗口里的提示答完即可（默认账号 `liuhao`，选 `0` 跳过模型），登录、聊天、模型管理的步骤与本文相同。

适用 Windows 10 / 11（64 位）。全程**不需要管理员权限**，安装包**不含任何模型**，也不需要你自己装 Python。

**没有 API Key 也能装**：首次设置第 3 步选“跳过”即可先完成安装和启动，
模型之后在 **系统设置 → 模型管理** 里补上。Key 的申请地址见第 3 步。

按下面四步走完，就能发出第一条消息。每一步都附了失败时怎么办。

  的校验值都登记在这同一份表里

> `0.1.1`，`0.1.2` 包待 r6 冻结重打后提供。

## 第 2 步：安装并第一次启动

1. 双击 `LiuHao-Setup-<版本号>.exe`。
   - Windows 弹出“未知发布者”：点 **更多信息 → 仍要运行**。这是自签名程序未导入信任时的正常提示。
   - 程序默认装到 `D:\LiuHao`，数据默认在 `D:\LiuHaoData`，不写系统目录，也不弹 UAC。
   - D 盘不可用（不存在 / 不可写 / 是可移动盘）时：
     程序目录自动回退到 `%LOCALAPPDATA%\Programs\LiuHao`（用户级目录，普通双击安装
     **不会弹 UAC**）；只有你主动“以管理员身份运行”安装包时，程序才回退到 `%ProgramFiles%\LiuHao`。
     数据目录：安装向导会多出「数据目录」页让你确认/改选，D 盘不可用时通常预填
     `%LOCALAPPDATA%\LiuHao\data`。没有检测到可用非系统盘时，数据目录和备份目录都
     自动落到 `%LOCALAPPDATA%\LiuHao`，安装继续、不会中断；向导会提示
     「没有检测到非系统盘，数据与备份都在 C 盘，建议预留空间」。也可以手动改选
     非系统盘目录（例如 `E:\LiuHaoData`）。
     回退原因和实际位置会写在安装向导的「准备安装」页；只有发生回退安装时，
     程序目录下才会生成 `安装位置说明.txt`（正常装到 D 盘不生成）。
   - 已经装在 C 盘的老用户：覆盖安装/升级保持原位置不变，不会被新默认值改走。
   - 实际数据目录以程序目录下的 `data-dir.txt` 为准，下面提到 `D:\LiuHaoData`
     的地方都按这个文件的实际内容理解。
2. 安装向导弹出时读过说明，直接下一步；建议保留“创建桌面快捷方式”。
3. 安装完成后勾选“立即启动”，或双击桌面上的 **LiuHao AI OS · 鎏灏智能中枢**。

启动后会出现：

- 一个**「LiuHao AI OS · 鎏灏智能中枢」状态窗口**，显示「网关：」「启动：」「健康：」「控制台：」几行，
  **不需要输入任何内容**；任务栏通知区（托盘）同时出现鎏灏图标（绿色=运行中、红色=有错误、灰色=已停止）；
- 一个标题为 **「鎏灏首次设置」** 的窗口（仅当这台机器还没有可登录账号时出现），
  按“第 3 步”填五步即可。

> 双击快捷方式启动的是**托盘常驻**形态：**关闭状态窗口只是隐藏到托盘**，网关继续运行，
> 不会停服。真正退出请用托盘右键菜单的 **退出（停止网关并关闭托盘）**（状态窗口里的同名按钮等效）。
> 托盘菜单的「停止服务（仅停网关，托盘保留）」只停网关、托盘仍保留。需要命令行模式（排障用）时，
> 在程序目录运行 `LiuHao.bat --console`；源码仓库用 `scripts\start_liuhao.py`。

服务默认监听 `8080`（地址 `http://127.0.0.1:8080`）。**首启向导里可以换端口；日常启动如果端口被占，
会告诉你占用原因并给出处理办法**，见下面的“端口被占用怎么换”。

**这一步失败怎么办**

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 双击安装包没反应 | SmartScreen 拦截 | 右键 → 属性 → 勾选“解除锁定”，再双击；或按上面的“更多信息 → 仍要运行” |
| 双击快捷方式后既没有状态窗口，托盘也没有鎏灏图标 | 安装不完整或上次进程残留 | 重新运行安装包覆盖安装；仍不行看下面的“起不来怎么办：三步” |
| 状态窗口显示“启动失败”并停在错误原因 | 安装目录缺文件 | 重新安装；若提示运行时不完整，说明安装包损坏，重新下载 |
| 启动时提示“端口 8080 已被占用” | 上次的鎏灏没退干净，或别的程序占用了 8080 | 程序不会自动换端口。窗口会写清占用原因（占用者 PID / 程序名）并给出处理办法：**关掉占用程序再试**（先关掉占用者或重启电脑），或在首启向导 / 启动入口换一个空闲端口 |
| Windows 防火墙弹窗 | 程序监听本机地址，首次运行常见 | 勾选“专用网络”并允许；如果你只在同一台电脑上用，点“取消”也不影响本机访问 |

### 端口被占用怎么换（0.1.1+）

1. 看窗口最后几行：会写“网关端口 8080 已被占用（占用者：PID … 程序名）”——这就是占用原因。
2. **处理一：关掉占用程序再试**：先关掉占用 8080 的程序（或重启电脑），再重新启动。
3. **处理二：换端口**：首启向导里可以换；已完成首启的机器在启动入口填一个空闲端口（例如 8081）后重新启动，不用改快捷方式。
4. 之后地址变成 `http://127.0.0.1:<你选的端口>`；以状态窗口「控制台：」那一行为准（`current_url.txt` 只是某次启动的快照，安装版 `LiuHao.bat` 启动会写、双击桌面图标不写，可能过期，不要依赖它）。
5. 纯命令行 / 无桌面时不会弹窗：逐行打印「处理一／处理二」，复制「处理二」下面那条命令
   （含引号）重跑即可（命令里已给出候选端口，通常是 8081）；**返回码 2 表示没有启动**。
   源码 / 命令行也可直接 `--api-port 8081` 指定端口。

## 第 3 步：首次设置（五步，模型可以跳过）

首次启动会弹出标题为 **「鎏灏首次设置」** 的窗口，底部按钮是 **上一步 / 取消 / 下一步**，
共五步：数据目录 → 管理员账号 → 选择模型（可跳过）→ 完成前请确认 → 自检结果。
第 4 页点 **完成并自检**，第 5 页点 **进入控制台**。**没有 Key 也能跳过模型配置**，安装和启动都不受影响。

> 在第 1～4 步点 **取消** 或直接关窗＝放弃本次设置：不会创建账号，也不会启动控制台；
> 重新双击桌面图标可再次进入向导。点过 **完成并自检** 后再关窗不会丢设置，服务照常启动。

### 3.1 第 1 步 · 数据目录

- 默认就是你的数据目录（通常 `D:\LiuHaoData`），**一般不用改**。
- 需要换位置就点 **浏览…** 选一个文件夹；换目录会换一套账号与数据，旧目录不会被迁移。
- 窗口下方会显示日志文件路径，方便排错。

### 3.2 第 2 步 · 管理员账号

字段逐字如下：

- **账号（英文）**：例如 `liuhao`（就是以后登录用的账号）
- **显示名（可中文）**：中文或英文都行，例如 `鎏灏`；留空则与账号相同
- **登录密码 / 确认密码**：输入时屏幕不显示，这是正常的。密码至少 8 位，且同时包含字母和数字。

填完点 **下一步**。

> 首次设置**不会**自动发放恢复码。登录后建议立刻到左侧 **恢复码** 页生成一枚并保存（见“忘记密码”一节）。

### 3.3 第 3 步 · 选择模型（可跳过）

这一页还可以改**服务端口**（默认 `8080`）。三个选项，默认选中第一个：

- **跳过，稍后在「系统设置 → 模型管理」里添加**：推荐第一次安装先选这个，进入控制台再配。
- **本机 Ollama（需先安装 Ollama 并 pull 模型）**：填 **模型名**（默认 `qwen2.5:7b`）和
  **地址**（默认 `http://localhost:11434`）。使用期间保持 Ollama 在运行。
- **云端 API Key（OpenAI 兼容，如 DeepSeek）**：填 **base_url**（默认
  `https://api.deepseek.com/v1`）、**模型名**（默认 `deepseek-chat`）、**API Key**。
  窗口会提示“Key 只保存在本机，由 AES-256-GCM 加密后写入数据库，不会写进明文配置。”

**0.1.1+ 支持的服务商**（在控制台「系统设置 → 模型管理」里可选）：OpenAI、DeepSeek、
月之暗面 Kimi、Anthropic、Google Gemini、本地 Ollama，以及“OpenAI 兼容”自定义端点。
预设只是帮你把端点和模型名填好，**不是白名单**；模型名可以自己填，以服务商文档为准。

**去哪里申请 API Key（以 DeepSeek 为例）**

1. 打开 <https://platform.deepseek.com> 注册并登录。
2. 在「API Keys」页创建 Key，复制形如 `sk-...` 的字符串（按量计费）。
3. 回到「鎏灏首次设置」第 3 步，选“云端 API Key”，填 **base_url**
   `https://api.deepseek.com/v1`、**模型名** `deepseek-chat`、粘贴 **API Key**。

其他 OpenAI 兼容服务同理：到对应平台的「API Key / 密钥」页创建，
base_url 与模型名以该平台文档为准。**没有 Key 就选第一项跳过**，
安装完成后随时到 **系统设置 → 模型管理** 补上，不需要重装或重启安装程序。

在第 4 页点 **完成并自检**、第 5 页点 **进入控制台** 后，服务继续启动，
控制台在原生窗口（WebView2）中**自动打开**登录页（默认 `http://127.0.0.1:8080`）。用刚建的账号登录，进入「总览」。
若窗口没有自动出现，检查托盘图标。网页模式（`--web`）才用浏览器，手动访问 `http://127.0.0.1:8080` 即可。
如果窗口报“端口 8080 已被占用”，程序**不会自动换地址**；按第 2 步的“端口被占用怎么换”处理后，
地址会变成你选的新端口。

地址以实际打开的控制台为准（桌面端是原生窗口；网页端＝浏览器访问，用 `--web` 启动或直接打开地址）。
`<数据目录>\config\current_url.txt` 只是启动器 `scripts/start_liuhao.py` 在某次启动时写下的快照
（安装版 `LiuHao.bat` 启动会写；双击桌面图标启动不写；源码 `start-liuhao.bat` 默认也不写），
可能是旧端口/死 pid，**不要以它为准**。

> 界面文字以已发布的 0.1.1 安装包为准；如果你看到的按钮/提示与此处不同，请截图反馈。

### 3.4 先验证再聊天（强烈建议）

「鎏灏首次设置」窗口**不会**替你验证 Key 是否有效。登录后先做一次连通性测试，比发消息失败后再猜要快得多：

1. 用刚才建的管理员账号和密码登录。
2. 点左下角的 **系统设置**，找到 **模型管理**。
3. 在你刚填的模型那一行点 **测试连接**。
4. 看到“连接成功（xxx ms）”就说明 Key、模型名、地址都对了。

测试失败时，界面会直接告诉你该改什么：

| 提示 | 含义 | 怎么办 |
| --- | --- | --- |
| `API Key 无效或没有权限。请检查 Key 是否填错、是否复制完整；建议重新生成后再试。` | Key 抄错、已过期、或没有该模型权限 | 重新复制 Key；确认 Key 与服务商匹配；确认账号有余额/权限 |
| `模型名不存在，或该接口地址不支持这个模型。请核对模型名称后重试。` | 模型名拼错，或这个 base_url 下没有这个模型 | 对照服务商文档改模型名；注意大小写和完整前缀 |
| `接口地址不可达。请检查地址、端口与网络连接是否正常。` | 地址错、少写 `/v1`、网络不通、本机服务没启动 | 检查 base_url；浏览器能打开服务商官网；本地模型确认 Ollama 正在运行 |
| `连接超时。请检查网络，或稍后再试。` | 网络慢或地址不可达 | 换网络重试；确认地址不是内网/公司代理拦截的地址 |
| `请求被上游限流（429）。请稍后重试。` | 请求太频繁或额度用尽 | 稍等再试；检查服务商额度 |
| 选 Ollama 却提示连不上 | Ollama 没启动，或模型没拉取 | 打开 Ollama 应用；在命令行执行 `ollama pull <模型名>` 后再测试 |

> 如果你用的是本机其他 OpenAI 兼容服务（例如 LM Studio），“测试连接”可能被安全策略拒绝；这不影响聊天。直接用第 4 步发消息验证即可。

**选错了想改怎么办？**

登录后到 **系统设置 → 模型管理**，编辑模型或新增一个，先点 **测试连接**；
通过后才能勾选 **设为默认模型**（没通过可以保存，但设置默认会被拒绝）。
保存后**下一条消息立即生效，不需要重启**，也不需要重装。

**怎么让它记住更长的上下文？**

鎏灏会按模型窗口自动裁剪历史：保留最近几轮，更早的内容折成摘要。如果模型本身支持更大的窗口（例如 128k），而界面里暂时还没有窗口设置，可以在启动前用环境变量手动调大：

```powershell
$env:LIUHAO_CONTEXT_WINDOW = "131072"
```

- 优先级：`LIUHAO_CONTEXT_WINDOW` > 模型配置里的窗口值 > 内置模型家族表（gpt-4o=128k、claude=200k、deepseek=64k 等）> 保守 8192。
- 取值范围 2048–1000000；填了非数字或超范围的值会被忽略并回落到内置值，同时在服务端日志留一条 warn（`evt=context.window.invalid`），程序照常运行。
- 这里只决定"一次发多少历史"，不会把模型的实际窗口变大；设得比模型真实窗口还大，上游仍可能拒绝。
- 该变量要在启动鎏灏的那个进程（启动器或终端）里设置，改完重启一次生效。

**用量和预算怎么算？**

鎏灏每轮对话都会先估算这次要花多少（输入 + 输出），再和可用额度比对；余额不够就**直接拒绝**，不会先花出去再报错。

- **默认额度是系统给的，不是你自己设的**：系统级 COST 配额默认 **100**（同一套系统资源账本）。所以初次使用看到额度时，不要以为自己填错过什么。
- **想调整**：在启动鎏灏之前设置环境变量 `LIUHAO_DEFAULT_COST_QUOTA`（例如 `$env:LIUHAO_DEFAULT_COST_QUOTA = "400"`），重启后生效。这是系统默认额度，不是每条消息的硬上限。
- **token 怎么估**：没有拿到服务商的真实用量时，按保守上界估算——**中文 1 个字 ≈ 1 token**，英文/符号约 **4 个字符 ≈ 1 token**。中文估得偏多是有意为之：宁可提前提醒，也不让请求在模型侧超限失败。
- **真实用量优先**：只要模型返回了真实 usage（输入/输出 token 数），就按真实值记账，估算只在拿不到真实值时才使用。
- 因此被拒绝时提示是 **「本次调用会超出可用预算（按保守 token 估算）」**——这是额度不够（可以调整额度或换更便宜的模型），不是权限问题，也不必去改权限设置。

## 第 4 步：发第一条消息

1. 控制台在原生窗口（WebView2）中自动打开；如果没出现，检查托盘图标。网页模式（`--web`）才用浏览器，手动访问 **`http://127.0.0.1:8080`**。
   - 地址以实际打开的控制台为准（桌面端是原生窗口；网页端＝浏览器访问，用 `--web` 启动或直接打开地址）。`<数据目录>\config\current_url.txt` 只是某次启动的快照（安装版 `LiuHao.bat` 启动会写、双击桌面图标不写），可能过期，不要以它为准。
   - 如果启动时提示“端口 8080 已被占用”，程序不会自动换地址；按第 2 步的“端口被占用怎么换”处理后再访问。
2. 用第 3 步建的管理员账号、密码登录。
3. 点左侧 **工作台**。在输入框里打一句话，例如“你好，介绍一下你自己”，回车发送。
4. 几秒内出现回复，就说明整条链路已经跑通。

**这一步失败怎么办**

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 控制台窗口或浏览器显示“无法访问此网站 / 连接被拒绝” | 服务没起来，或程序已退出 | 看托盘图标有没有鎏灏：有就点左键打开窗口确认“运行中”，没有就重新双击桌面快捷方式。仍不行按下面的“起不来怎么办：三步”排查 |
| 控制台打开的是 `8080`，但页面空白或还是旧界面 | 缓存 / 旧 Service Worker / 程序已退出 | 先看托盘图标在不在、窗口是否显示“运行中”；再按下面的“浏览器显示旧界面或白屏”处理（强刷 → 注销 Service Worker → 清站点数据） |
| 登录提示“未配置（无法登录）” | 首次设置没建成管理员（例如密码少于 8 位） | 用托盘菜单“退出”后再重新双击快捷方式，「鎏灏首次设置」会再次让你建账号 |
| 登录提示“账号或密码不正确” | 账号或密码不对 | 用「鎏灏首次设置」里建的账号。忘记密码：登录页点「忘记密码」，用恢复码重置；没有恢复码时见下面的“忘记密码：本机取恢复码”。登录后建议马上到左侧「恢复码」页生成一枚新码（0.1.1+） |
| 回复里出现 `返回 HTTP 401，详情已记录到服务端日志。`（前面带服务商名）或 `API Key 无效或已失效，请到「系统设置 → 模型管理」更新密钥。` | API Key 无效或被吊销 | 按第 3.4 节“测试连接”的 `API Key 无效` 处理 |
| 回复里出现 `模型不存在或已下线，请核对模型名（可点「测试连接」查看服务端返回）。` | 模型名不对或未开通 | 到 **系统设置 → 模型管理** 改正模型名，再点“测试连接” |
| 回复里出现 `返回 HTTP 503，详情已记录到服务端日志。` 或 `连不上模型服务。…` | 模型服务不可达 | 检查网络、base_url；Ollama 用户确认 Ollama 正在运行 |
| 回复开头是 `[演示数据] 还没有配置模型…` | 当前没有可用的真实模型，系统没有伪造回答 | 到 **系统设置 → 模型管理** 添加模型、点“测试连接”通过后勾选 **设为默认模型**，然后回到工作台重新发一条 |

## 左侧菜单巡览（登录后先认路）

左侧是同一份页面清单，按账号权限裁剪：**没有权限的入口直接不显示**，不是点进去才报 403。

- **总览 / 鎏灏管家**：总览看今天发生了什么；「鎏灏管家」是你下目标、它拆解分派并给结论的地方。
- **我的员工 / 能力注册表**：前者创建、改名、停用你自己的 AI 员工；后者只读展示系统预置了哪些能力。
- **业务中心 / 知识中心 / 记忆 / 工作台 / 目标与任务 / 项目 / 应用 / 数据中心 / 事件流**：日常干活、查资料、看产出与运行记录；其中「应用」页当前只列出内置的示例能力，**没有第三方插件的安装、发现或更新入口，也不显示旧插件**；旧插件直接调相关接口会返回 404，适配与可用性标注在 0.1.3 提供。
- **我的 Key**：管理你自己的模型 Key；根账号此项显示为「全部 Key」，可看整棵树并授权给成员。
- **生产预检**（根账号）：上线前体检，只给只读结论，不修配置也不改数据。
- **成员与权限管理 / 权限矩阵 / 角色模板**（根账号）：建成员、查看“谁能做什么”的矩阵、用角色模板批量授权。
- **备份与迁移 / 恢复码**（根账号）：备份当前账号数据；恢复码用于忘记密码时重置（换机与恢复码细节见对应章节）。
- **我的数据**：一键导出自己的会话/记忆/员工/知识库（人可读 ZIP），记忆与知识库也可回导。
- **审批中心 / 操作记录 / 信任 / 网络 / 身份与权限 / 工作区文件 / 系统状态**：治理与只读排查面；「工作区文件」用来浏览 AI 员工写出的产物。
- **关于与隐私 / 系统设置**：版本、数据目录、许可证与联网说明；系统设置仅根账号可见。

## 起不来怎么办：三步（0.1.1+）

按顺序做，每一步都可能直接解决问题。

1. **看状态窗口里的报错。** 启动失败时窗口会停在错误原因上（托盘图标此时是红色），也可以对照日志：
   - 提示「网关进程在启动过程中退出」或日志里 `[FAIL] ...`：安装不完整或运行时被杀软隔离，先覆盖安装；
   - “端口 8080 已被占用（占用者：…）”：按第 2 步的“端口被占用怎么换”；
   - 提示缺少文件：重新运行安装包。
2. **看日志。** 打开数据目录下的两个文件（默认 `D:\LiuHaoData`，实际位置看程序目录 `data-dir.txt`）：
   - `logs\launcher.log`：启动器与首次向导，记录“卡在哪、为什么退出”；
   - `logs\liuhao.log`：服务本身。
   先看最后 20～50 行即可，不要发整份。
3. **导出诊断包。** 能打开控制台（驾驶舱）时：左下角 **系统设置 → 遇到问题 → 一键诊断包 → 导出诊断包**。
   看到“已保存：<文件名>”或“已开始下载：<文件名>。请到浏览器的下载位置查看。”，
   就把这个 zip（形如 `liuhao-diagnostics-日期-时间.zip`）发给支持。
   诊断包包含版本、系统信息、健康检查与最近一段日志，**不含你的密钥**，路径中的用户名也已隐去。
   包里的 `SUMMARY.txt` 第一行就是一句人话结论（例如“端口 8080 被占用”），
   照着最后一行的“下一步”做即可；每份文件的含义见诊断包里的 `README.txt`。
   **包里少了几个文件？** 如果出现 `REDACTED-MEMBERS.txt`，说明有个别文件**仍含明文密钥、
   导出时被自动剔除**了。这不是软件坏了，而是在保护你的密钥；被剔除的通常是旧的日志文件，
   其余文件照常发出，技术支持仍能据此判断绝大多数问题，**你不需要额外补交什么**。
   想自己确认包是干净的（两步）：打开包里的 `REDACTED-MEMBERS.txt`——**里面没有条目就说明
   所有文件都在包里**；有条目时它只写文件名和命中条数，不会显示密钥本身。
   想确认包是**完整**的：打开 `README.txt` 的「本次是否完整」，那里写着
   「本次包含 N 个文件，未包含 M 个」——N 就是包里实际的文件数，N + M 是本次计划收集的总数，
   不用自己数文件。
   如果技术支持明确需要那份被剔除的日志：先退出鎏灏，把数据目录 `logs` 下的
   `liuhao.log`、`error.log`、`desktop-gateway.log` 都**改名备份**——把后缀 `.log`
   改成 `.log.bak-日期`（例如 `liuhao.log` → `liuhao.log.bak-20261108`），再导出。
   `.log.1` 这类轮转文件在控制台（网关）导出里本来就不会被收进包，桌面「生成诊断包」会收，
   建议一并改名。不要直接删除，那里可能有排查要用的证据。
   打不开控制台时，直接发第 2 步的两个日志文件，并附上窗口最后几行。
   **控制台根本打不开也能导：** 在程序目录打开命令行执行
   `runtime\python.exe scripts\start_liuhao.py --diagnose`（源码目录用
   `.venv\Scripts\python.exe scripts\start_liuhao.py --diagnose`）。
   它不启动服务，只做离线检查，最后打印一行 `[OK] 诊断包已生成：<路径>`。

## 我的软件打不开：六类故障对照（0.1.1+）

先认日志，再对照下表。日志在数据目录（默认 `D:\LiuHaoData`，实际位置看程序目录
`data-dir.txt`）下：

- `logs\liuhao.log`：服务主日志，正常与失败都在这里；
- `logs\error.log`：只记错误，行数少，适合先看；
- `%LOCALAPPDATA%\LiuHao\logs\bootstrap.log`：**数据目录和日志目录都写不进去时**
  唯一还会留下记录的地方（文件叫 `bootstrap.log`，不是 `.log` 目录里的）。
  如果它不存在，再看程序目录下的 `<程序目录>\bootstrap.log`（启动器/桌面壳失败时写在那里）。

用记事本打开后按 `Ctrl+F` 搜“看到什么”那一列的原样文字即可。

| 故障 | 日志里看到什么（原样搜索） | 意思 | 你该做什么 |
| --- | --- | --- | --- |
| 端口被占用 | `evt=startup.check ... port=8080 port_bindable=0 port_state=serving`；启动窗口另有“端口 8080 已被占用（占用者：…）” | `port_bindable=0` = 绑不上；`port_state=serving` = 有别的程序正在监听这个端口，`occupied` = 绑不上但也连不上（多为独占绑定或防火墙） | 换端口重启（窗口里选「换一个端口继续」，或 `--api-port 8081`）；或在任务管理器结束占用进程。诊断包 `ports.json` 会写出进程名与 PID |
| 数据/日志目录不可写 | `bootstrap.log` 里 `evt=boot.logdir.failed path=… winerror=183 errno=17 free_bytes=… action="…"`；`evt=boot.instance_lock.failed`（连实例锁都抢不到）；或 `evt=startup.check ... data_writable=0` / `log_writable=0`；`evt=boot.data_dir.unwritable` / `evt=boot.log_dir.unwritable` | 程序没有该目录的写权限（`winerror=5` / `errno=13`），或磁盘已满（看 `free_bytes`）。`winerror=183` 表示路径上已有同名文件/目录挡住建不了（常见于手动改过数据目录）；日志目录不可写时主日志本身也写不出来 | 权限问题：把数据目录改到当前用户可写的位置（例如 `%LOCALAPPDATA%\LiuHao\data`），或让管理员给目录写权限，并检查安全软件拦截；`183`：把挡路的同名文件改名或删除；磁盘满则清理后重启 |
| Key 无效或额度耗尽 | `upstream HTTP failure status=401 kind=invalid_key`；或 `evt=llm.call.failed ... status=401 error_class=AuthenticationError key_fp=sha256:xxxxxxxx`；额度耗尽是 `status=402 kind=quota_exhausted`（有的服务用 `status=429`） | `status=401/403` = Key 填错、被撤销或没权限；`status=402` + `kind=quota_exhausted` = Key 有效但余额/额度用完了。`key_fp` 只是指纹，用来确认“换没换 Key”，不是 Key 本身 | 打开 **系统设置 → 模型管理**，重新填 Key 并点 **测试连接**；额度耗尽去模型服务商充值或换 Key。用 `key_fp` 前后对比可确认是否真的换了 Key |
| 模型服务连不上 | `evt=llm.call.failed ... error_class=ConnectionRefused errno=10061`；`error_class=Timeout errno=10060 timeout_s=…`；`error_class=DNSFailure errno=11001 dns_host=api.…` | `10061` = 对方端口拒绝连接（地址/端口错，或服务没开）；`10060` = 连接超时（网络、代理、防火墙）；`11001` = 域名解析失败（DNS 或域名拼错） | `10061`：核对 base_url 与端口，Ollama 用户确认 Ollama 已运行；`10060`：检查网络/代理/防火墙；`11001`：检查域名拼写和 DNS。`host=` / `dns_host=` 写明连的是哪里 |
| 数据库损坏 | `evt=db.open.failed subsystem=audit path=data/audit_store.db sqlite_msg="DatabaseError: file is not a database" … action="degraded: …"`；紧接着 `AUDIT CHECKPOINTER NOT STARTED -- 审计库打不开…`；汇总行 `evt=startup.degraded components=[…] ready=false` | 某个具体的库打不开（`path` 就是相对数据目录的那个文件），常见原因是文件损坏、被别的程序锁住或没有权限。`AUDIT CHECKPOINTER NOT STARTED` 表示审计检查点这次没有运行（不是整个服务崩了） | 先备份整个数据目录；再把 `path=` 指向的库文件改名或移走，重启后会自动重建空库；若是权限问题，修复该文件权限 |
| 前端静态资源缺失 | `evt=console.asset.missing path=/assets/index-xxxx.js method=GET action="缺少构建产物：…"`；或 `evt=startup.check ... console_dist=… console_index=0` | `console_index=0` = 连 `index.html` 都找不到（安装不完整）；只有 `console.asset.missing` = 入口在、它引用的 JS/CSS 不在，页面会白屏 | 用同一个安装包覆盖安装（补齐 `console` 目录），不要只复制可执行文件；源码运行则在 `apps/console/console` 执行 `npm run build` |

补充：如果 `logs\liuhao.log` 里**连一条新的 `evt=startup.check` 都没有**，说明服务在写
业务日志之前就退出了——先看 `logs\launcher.log` 的最后 20 行和 `bootstrap.log`
（常见事件：`evt=boot.instance_lock.failed`、`evt=boot.logdir.failed`、
`evt=boot.startup.failed`），再按上面的“三步”排查。

## 忘记密码：本机取恢复码（0.1.1+）

### 手里有恢复码

1. 登录页点 **忘记密码**。
2. 填恢复码（之前生成并保存的那串，形如 `RC-...`）和新密码（至少 8 位）。
3. 点 **重置并进入**。恢复码用一次就失效。
4. 登录后马上生成新码：左侧导航 **恢复码**（仅根账号可见）→ 勾选“我明白轮换后旧恢复码立即失效，需要重新保存。” → **生成新的恢复码**。页面会直接显示新码，可 **复制** 或 **下载恢复材料（未加密）**；旧码立即失效。

### 老账号没有恢复码

**首次安装时「鎏灏首次设置」不发恢复码**，所以第一次忘记密码就是走这条路。

1. 用启动器**自动打开的那个原生窗口**进入登录页（双击快捷方式后弹出的那个）；
   手动在浏览器里输入 `http://127.0.0.1:8080` 打开的页面**不算本机证明**，这一步会失败。
2. 点 **忘记密码** → **没有恢复码？在本机生成**。
3. 页面会直接显示新恢复码，标题是“新的恢复码只显示这一次，请立刻抄下来，或存进密码管理器。”
   下面就是形如 `RC-...` 的码，旁边有 **复制** 按钮。抄下来（或点复制），再填新密码
   （至少 8 位）→ **重置并进入**。
4. 后台把码写进本机加密交接文件（`<数据目录>\config\recovery_code.txt`，Windows 用当前
   登录用户凭据加密，不是明文），交给页面一次后**立即删除文件**（用完即焚）。
5. 如果提示“本机恢复流程还需要桌面端的一次性证明…”，说明当前页面不是启动器打开的：
   关掉这个标签页，回到桌面**重新双击快捷方式**，用新打开的页面重试。
   不要反复点“在本机生成”，每点一次都会让上一枚码失效。
6. 如果提示“已存在有效的恢复码；请使用已有的码，或登录后在“恢复码”页重新生成”，
   说明这台机器上已经有一枚可用码；用你保存的那枚即可。
   想换新码，用能登录的根账号进入左侧 **恢复码** 页轮换。

> 恢复码等同于账号最高权限：不要发到群里、不要写进工单；下载的“恢复材料”是**未加密**明文，按密码保管。

## 浏览器显示旧界面或白屏（0.1.1+）

1. 先确认托盘图标还在、状态窗口显示“运行中”，且没有端口报错。关掉状态窗口只是隐藏到托盘，网关继续运行；只有托盘菜单“退出”才会真正退出。
2. **强刷**：在页面按 `Ctrl + F5`（或 `Ctrl + Shift + R`）。多数“还是旧界面”到这一步就好。
3. **注销 Service Worker**：
   - 按 `F12` 打开开发者工具；
   - 顶部选 **Application（应用）** → 左侧 **Service Workers**；
   - 在 `http://127.0.0.1:8080` 那一行点 **Unregister（注销）**；
   - 关闭开发者工具，重新打开 `http://127.0.0.1:8080`。
4. **清站点数据**：开发者工具 → **Application（应用）** → 左侧 **Storage（存储）** → **Clear site data（清除站点数据）** → 刷新页面。
   这会清掉这个地址下的本地登录状态，需要重新登录；账号、Key、聊天记录都不受影响。
5. 用无痕窗口对照：无痕正常、普通窗口不正常，基本就是缓存或 Service Worker 问题，按第 2～4 步处理。
6. 换过端口时：旧标签页仍指向旧端口，用状态窗口「控制台：」里的新地址重新打开。

## 安装与卸载常见问题（Windows）

### 出现“未知发布者 / SmartScreen 已阻止”

安装包使用本项目的**自签名代码签名证书**（主体 `CN=鎏灏智能中枢, O=LiuHao AI OS, C=CN`），
不是公开权威 CA。未导入信任的机器上，Windows 会显示：

- “Windows 已保护你的电脑”
- “未知发布者”

继续安装：

1. 点提示框里的 **更多信息**。
2. 点 **仍要运行**。
3. 安装向导出现后，按提示继续。

首次安装出现“未知发布者”是预期行为，不是安装包损坏或被篡改。想避免这个提示，
可以先运行与安装包放在同一目录的 `信任签名证书.cmd`（只信任当前 Windows 用户，
不需要管理员权限；同目录的 `LiuHao-CodeSigning.cer` 是它导入的证书），再双击安装包；
不导入信任也可以直接按上面三步安装。

导入信任只在这台电脑的当前 Windows 用户下生效，签名状态会显示“有效”，但这不等于
“已验证发布者”的公开信任：换一台电脑或换一个 Windows 账户后，提示仍可能出现。

这不是“病毒告警”，但也不等于可以无条件信任。只从公网发布页
<https://yhd952700-prog.github.io/liuhao-release/> 或构建输出目录 `dist/installer/` 取包，
并核对发布页/`SHA256SUMS.txt` 的 SHA256；来源不明的安装包不要运行。

如果点了“更多信息”仍没有“仍要运行”：右键安装包 → **属性** → 勾选 **解除锁定** → 再双击。

### 杀毒软件或系统提示拦截

自签名 / 信誉不足的程序可能被杀软误报，甚至直接隔离。处理顺序：

1. 先确认安装包来源可信，并核对 SHA256（见第 1 步）。
2. 在杀软里把被隔离的文件**恢复**，把程序目录（默认 `D:\LiuHao`，回退时 `%LOCALAPPDATA%\Programs\LiuHao`）加入信任或排除。
3. 重新运行安装包或重新启动程序。

不要为了安装关闭整个杀软的实时防护。公司电脑被安全策略锁定时，联系 IT 放行。

如果被拦的是 `runtime\python.exe`，现象通常是双击后状态窗口立刻报“启动失败”，或托盘里根本没有鎏灏图标。恢复这个文件并加信任后再启动。

## 数据在哪里、怎么备份

所有用户数据都在：

`D:\LiuHaoData`（安装时另选目录则以 `data-dir.txt` 为准；启动器读不到 `data-dir.txt` 时才退到 `%LOCALAPPDATA%\LiuHao\data`）

覆盖安装和升级只替换程序目录，不动数据目录。
升级入口在 **系统设置 → 软件更新**（仅根账号可见）：**未配置更新源时「检查更新」按钮是禁用的**并写明原因，不是坏了；配置了更新源才能检查/下载/校验/应用。没有更新源时仍用覆盖安装。
运行 `LiuHao.bat` 时以程序目录下的 `data-dir.txt` 为准，不要凭记忆猜路径。

实际访问地址看状态窗口里的 **「控制台：」**。启动器还会在 `<数据目录>\config\current_url.txt` 写下
`url=` / `port=` / `pid=` 快照（安装版 `LiuHao.bat` 启动会写、双击桌面图标不写），但它可能过期，不要以它为准。
日志在 `<数据目录>\logs\`，启动器与向导看 `launcher.log`，服务本身看 `liuhao.log`。

### 备份（同机留档 / 回滚）

登录后可用左侧导航 **备份与迁移**（仅根账号可见）：
「导出备份」选范围（整棵树 / 仅我的账号）、设口令、勾选确认后点 **导出并下载**；
「从备份迁移到本机」只在全新实例（本机还没有任何账号）首次启动时可用，本机已有账号时不能导入。
没有界面条件时，可以在**同一台电脑、同一个 Windows 用户**下手动复制整个数据目录做留档：

1. 先退出鎏灏：托盘菜单“退出”（关窗口只是隐藏到托盘）。
2. 打开程序目录的 `data-dir.txt`，按里面记录的路径打开数据目录。
3. 把整个数据文件夹复制到 U 盘、移动硬盘或另一块磁盘。
4. 恢复时，先退出鎏灏，再把备份覆盖回同一位置。

注意：数据目录里还有一个 `data` 子文件夹，里面的 `model_config.key` 和 `model_registry.sqlite3` 必须一起备份。缺一个，已保存的 API Key 就解不开。

> **换电脑不要直接拷数据目录。** 模型主密钥、身份签名密钥和 JWT 签名密钥
> 都用 Windows DPAPI 绑定在**这台电脑的这个 Windows 用户**上。把整个数据目录
> 拷到另一台电脑（或在同一台电脑换一个 Windows 用户）后，程序会发现密钥解不开，
> 打印中文提示「本机密钥无法在此机器解密，请用账号备份包恢复或重新生成。」，
> 并**保留原密文、不覆盖**——结果是模型 Key 解不开、登录签名不可信。
> 这属于**不支持场景**。换机**必须**走下一节的带口令备份包；导入时由新电脑的
> DPAPI 重新绑定密钥。手动整目录复制只适用于同机留档与回滚。

### 换电脑怎么办（导出 → 拷过去 → 导入）

换到新电脑后，仍然能用原来的账号密码登录，看到原来的成员和会话，直接接着发消息，
模型 Key 也不用重填。前提：**新电脑必须是一台还没有任何账号的全新实例**
（刚装完第一次打开、还没创建账号）。

1. **旧电脑导出**
   用主账号登录 → 左侧 **备份与迁移** → 「导出备份」里范围选 **整棵树** →
   设一个口令（至少 8 位，自己记住）→ 勾选确认 → 点 **导出并下载**。
   浏览器会下载一个 `liuhao-backup-all-<时间戳>.json` 文件。
   口令**不写进文件**，丢了就打不开；请把口令记在别处，不要和文件放在一起。
2. **拷过去**
   把这个 json 文件用 U 盘、移动硬盘或局域网拷到新电脑的任意目录。
   不用改文件名，也不要解压或编辑内容。
3. **新电脑导入**
   装好并启动鎏灏 → 在浏览器登录页点 **「从备份迁移到本机」** →
   选择第 2 步的文件 → 输入第 1 步的口令 → 导入完成后用**原来的主账号和密码**登录。

导入后花一分钟确认这几件事（任何一项不对，说明包不完整，回旧电脑重新导出）：

- **成员**：左侧「成员与权限管理」里能看到原来的成员和权限。
- **会话**：打开原来的会话，历史消息都在；发一条新消息能正常返回。
- **模型 Key**：系统设置 → 模型管理里原来的 Key 显示可用，不需要重填。
- **记忆与文件**：原来的记忆、上传的文件都还能读到。

几点说明：

- 导入只在新电脑上执行一次。本机已经有账号时，登录页不会出现这个入口，
  服务端也会拒绝导入，现有数据不会被覆盖。
- 旧电脑不受影响：导出不会让旧电脑掉线，也不会吊销旧电脑的登录状态。
- 旧电脑上的登录状态**不会**带到新电脑；导入后需要重新登录一次（用原密码）。
- 换机**只认带口令的备份包**。手动复制整个数据目录不能换机（密钥绑在原电脑的
  Windows 用户上，见上一节），只用于同一台电脑的留档与回滚。

| 导入时遇到 | 原因 | 怎么办 |
| --- | --- | --- |
| 登录页没有「从备份迁移到本机」 | 本机已经创建过账号 | 换一台全新实例；不要改用整目录复制换机 |
| 提示口令错误 | 口令记错（文件里没有口令） | 找回第 1 步设置的口令；确实忘了就回旧电脑重新导出 |
| 提示包无效或版本不匹配 | 文件被编辑/损坏，或来自更旧的版本 | 不要改文件；用同版本重新导出后再导入 |

### 两条打包路线：界面导出 vs CLI 备份（实测差分）

「备份与迁移」页面里的导出和命令行备份**不是同一个东西**。它们各自能带走什么，
请按用途选，不要以为随便一个包都能换机登录。

下表是**同一份数据**分别走两条路线后逐项核对的结果（数据规模：2 个账号、
3 名员工、2 个目标、5 条账号记忆、6 条内核记忆、4 轮会话、2 篇知识库文档、
2 条模型配置、5 个普通附件 + 1 个 66 MB 大附件）。复现命令见本节末尾。

图例：**都带** = 两条路线恢复后都可用；**仅 CLI** = 只有命令行加密包带；
**都不带** = 两条路线都不带。

| 项目 | 界面导出 → 新机导入 | CLI 加密备份 → 空目录恢复 | 结论 | 差异理由 |
| --- | --- | --- | --- | --- |
| 账号树（含根/成员层级） | 2 个 | 2 个 | 都带 | — |
| 登录凭据（PBKDF2 哈希，原密码可登录） | 2 条 | 2 条 | 都带 | — |
| 员工 / 目标 | 3 / 2 | 3 / 2 | 都带 | — |
| 账号记忆 / 内核记忆 / 个人画像 | 5 / 6 / 0 | 5 / 6 / 0 | 都带 | — |
| 会话轮次 | 4 | 4 | 都带 | — |
| 知识库 | 2 向量 / 2 文档 | 2 向量 / 2 文档 | 都带 | — |
| 模型配置 | 2 条 | 2 条 | 都带 | — |
| 模型 Key（换机后可用） | 2 个密文，含成员 | 2 个密文 + 原始主密钥（口令包内） | 都带 | 界面用口令保险箱重封；CLI 在口令包内带原始主密钥，导入时用新机 DPAPI 重新包裹 |
| 模型主密钥 `model_config.key` | **不带** | 带（原始材料，导入时重包） | **仅 CLI** | 它能解开所有 Key；界面路线宁可换机时用口令重新加密，也不让它离开本机 |
| 身份签名 `integrity.key` | **不带** | 带（原始材料，导入时重包） | **仅 CLI** | 只在本机有意义；CLI 以原始材料入包，导入时绑定目标机 |
| 审计账本 `audit_store.db` | **不带** | 带 | **仅 CLI** | 界面只迁移账号域数据；审计链要配原机密钥才能验，单独带库反而让人误以为可验证 |
| 服务环境 `app.env` | **不带** | 带（JWT 与 `SECRET_KEY` 原始材料，导入时重包） | **仅 CLI** | 含 JWT/服务密钥，界面路线不碰 |
| 备份尝试计数 `account_backup.sqlite3` | 不带 | 不带 | 都不带 | 实例本地限流状态，迁移过去会把新机锁在错误计数上 |
| 附件 ≤64 MB（上传/生成的图表文档） | 5 个 / 4,198,976 B | 5 个 / 4,198,976 B | 都带 | 逐文件哈希一致 |
| 附件 >64 MB（示例 66 MB） | 不带，列入回执 `skipped` | 带 | **仅 CLI** | 界面有单文件 64 MB 上限，超限跳过并明说；CLI 直接读盘无此限制 |
| 工件索引 `liuhao_artifacts.db` | 带，并改写 5 行路径 | 带，并改写 5 行路径 | 都带 | 恢复时把源机绝对路径改写成新机路径 |
| 执行日志 `liuhao_execution.journal` | 带 | 带 | 都带 | 同上，日志里的路径字段一并改写 |
| 日志 / 诊断包 | 不带 | 不带 | 都不带 | 原机运行痕迹，含旧用户名与旧盘符；新机会自己重新生成 |

读到「仅 CLI」时请注意：**它们不是界面路线忘了做，而是刻意不带**。界面导出的
定位是「换机能登录、能接着干活」，它不搬本机的信任根（主密钥、身份签名密钥）
和账号域之外的审计库。要整机搬迁，用 CLI 加密包（口令加密，导入时重新绑定目标机）；
**不要**用整目录冷拷贝换机。

界面导出还刻意不带这些**本机文件**：`config\human_identities.json`（身份注册表）、
`config\auth_secrets.json`（凭据库）、`data\model_config.key`（模型主密钥）、
身份签名 `integrity.key`。它们只在本机有意义；换机所需的账号记录、PBKDF2 登录
凭据与模型 Key 密文另有口令保险箱封装，所以不靠这些文件也能登录。
另外，`backup create` **不带** `--encrypt` 时是明文备份，会跳过上述凭据和密钥
文件，只适合数据留档，**不能**换机登录。

带口令的 CLI 加密包对三把密钥的形态有明确约定：包内是**原始密钥材料**，
不出现 `LIUHAO-DPAPI-1:` 这类本机密文；恢复时由目标机的 DPAPI 重新包裹。
所以换机只能走这个口令加密包，且口令不要和包放在一起。包里也绝不包含
`logs\`、`diagnostics\`、`*.log`/`*.lock`/`*.tmp` 以及 SQLite 的
`-wal`/`-shm`/`-journal` 运行痕迹。

#### 附件到底带不带

- **界面导出**：工作区里你上传的文件、程序生成的图表和文档**随包带走**，
  上限是**单文件 64 MB、整包 128 MB**。超过单文件上限的文件不会被静默丢弃：
  导出回执的 `manifest.skipped` 里会列出文件名，页面上的说明也会写「另有 N 个
  文件因超过单文件 64 MB 上限未随包」。整包超过 128 MB 时导出直接失败并提示
  「备份内容过大，无法一次导出」，不会给你一个缺了文件的包。
- **CLI 加密备份**：工作区文件全部随包，没有单文件上限；回执里的
  `attachments` 会给出实际带走的文件数与字节数。
- **日志与诊断包两条路线都不带**。它们是原机运行痕迹（含旧用户名、旧盘符），
  新机会重新生成。需要留档请在原机用「导出诊断包」单独保存。

#### 目标目录：只接干净的空目录

命令行恢复**只接受空目录**，三种情形分别是：

| 目标目录状态 | 行为 | 提示 |
| --- | --- | --- |
| 目录不存在 | 正常恢复并创建 | 成功回执 |
| 目录存在且完全为空 | 正常恢复 | 成功回执 |
| 目录里已有另一套完整数据（含 `config`、`data`、`workspace`、`memory_store.db` 等任一） | **拒绝**，一个字节都不写 | 「目标目录里已经有一整套数据……请换一个空目录」 |
| 目录里只有零散文件（哪怕只有一个） | **拒绝**，不做合并 | 「目标目录不是空目录……这个目录不干净，请换一个空目录再恢复；程序不会把新数据和旧文件合并」 |

拒绝发生在**写盘之前**：解密、校验、试写都在临时目录里完成，失败时目标目录
逐文件保持原样，临时目录也会被清理，不会留下半截文件。

#### 换机后路径可移植

恢复不会把源机的绝对路径原样带过来。实测覆盖了：

- 配置文件、日志目录：按新机数据目录重新定位；
- 知识库、工件目录：工件索引 `liuhao_artifacts.db` 的 `workspace`/`abs_path`
  按新机根目录重算（实测改写 5 行）；
- SQLite 里的路径字段：执行日志 `liuhao_execution.journal` 的
  `journal_events.payload`、账号记忆 `account_memory.sqlite3` 的
  `account_memory_migrations.details` 里的旧路径文本，按前缀替换成新机路径。

所以源机数据在 `D:\LiuHaoData`、新机装到别的盘或用了别的用户名时，
恢复后不会出现「文件都在但打不开」。恢复完成后的扫描确认两条路线都
**没有源机绝对路径残留**（复现见本节末尾命令）。

#### 命令行示例

```bat
set LIUHAO_DATA_DIR=D:\LiuHaoData
set LIUHAO_BACKUP_DIR=D:\LiuHaoBackups

REM 会直接改动数据，执行前先备份
REM 导出并加密（必须给口令；加密包才带身份库/主密钥）
runtime\python.exe -m src.cli backup create --encrypt --password "你的口令" --description "换机"

REM 在新机器上恢复到空目录（目标目录必须为空）
runtime\python.exe -m src.cli backup restore <backup_id> --password "你的口令" --target D:\LiuHaoData
```

恢复会把 `config\`、`memory_store.db`、`data\`、`workspace\` 按真实布局铺开；
目标目录只要已含这些内容或任何零散文件就会被拒绝，避免把两份数据拼在一起。
恢复成功后，让程序使用这个目录（把路径写进 `data-dir.txt`，或设置
`LIUHAO_DATA_DIR`），再打开状态窗口「控制台：」里的地址，用原账号登录即可继续派活。

复现上面两张表与路径扫描：

```bat
runtime\python.exe scripts\acceptance\backup_routes_diff_e2e.py
```

### 导出成「自己能看懂」的目录（我的数据）

不是换机，只是想把自己的东西留一份、随时能用记事本打开看：

1. 用你的账号登录 → 左侧 **我的数据** → 点 **导出 ZIP**（不需要口令）；
2. 解压后先看 **INDEX.md**：它逐份写明目录里每个文件是什么；
3. 看会话直接打开 `conversations/001-xxx.md`，是带时间的对话全文，
   不是数据库文件。

包里有什么：会话（Markdown）、记忆（`memories.md` / `memories.json`）、
目标（`goals.md` / `goals.json`）、员工清单（`employees.md` / `employees.json`）、
知识库、用量（`usage.csv`）、你自己名下的工作区文件。

只有**记忆**和**知识库**能导回来（页面上的「只回导记忆与知识库」两个按钮），
重复导入不会产生副本。**会话、目标、员工清单、工作区文件是只读归档**：
它们没有安全的"重放"语义，页面不会假装导入成功。要整机换电脑，请用上面的
「备份与迁移」加密凭据包，那才是双向的。

这个 ZIP 不含其他成员的数据，也不含任何模型 Key、登录令牌、恢复码；
疑似凭据的文件（`.env`、`*.key`、恢复码文件等）在打包时会被跳过，
并在 manifest 里记账。

### 口令丢了怎么办（没有后门）

- **界面导出的 `.json`**：口令只用来解包，文件里没有口令。口令丢了，这个包就
  打不开；已导入到新机盘的账号不受影响。唯一出路是**回旧电脑用同一版本重新导出**
  （前提是旧电脑的数据还在）。
- **CLI 加密包 `.lhbak`**：口令经 PBKDF2-SHA256（20 万次）派生密钥，再用
  AES-256-GCM 加密。**没有万能口令、没有管理员找回、没有"跳过口令"开关。**
  口令丢失只能回源机重新导出；源机数据也丢了，就只剩明文备份里的非密钥数据。
- `LIUHAO_BACKUP_PASSWORD` 只是省得每次输口令的传参方式，不会写进包、不会写日志。
  不要把口令和备份包放在同一个 U 盘/同一台机器上。
- 错口令、缺口令、包被截断都会**在写盘前**失败，并给出中文原因；恢复目标目录
  保持为空，不会留下"恢复了一半"的数据。

### 实测：加密备份的耗时与体积

在 Windows 开发机、`python -m src.cli`、同一块 SSD 上多次实测（数据来自验收脚本）：

| 数据目录 | 加密包 | 导出（快照+编码） | 加密（AES-256-GCM） | 恢复（解密+铺开） |
| --- | --- | --- | --- | --- |
| 5.2–5.4 MB / 26 文件 | 0.2 MB | 1.5–5.7 秒 | 0.15–0.22 秒 | 1.1–3.3 秒 |
| 13.3–13.5 MB / 30 文件 | 11.0 MB | 1.7–8.8 秒 | 0.5–0.66 秒 | 1.1–5.7 秒 |
| 37.4–37.5 MB / 30 文件 | 43.3 MB | 5.4–6.1 秒 | 1.8–2.0 秒 | 2.5–3.3 秒 |

- 导出耗时受磁盘、杀毒软件扫描与机器负载影响，同一命令多次实测可能差数倍；
  上表是本机多次实测的范围，不是承诺值。恢复一般是 1–6 秒。
- 包体积主要跟数据本身有关：文本/JSON 压得很好（5.2 MB → 0.2 MB）；
  已经是随机/压缩内容（示例里的大文件）基本不压，包会和数据一样大。
- 恢复时间包含解密、解压、按布局落盘；口令派生有约 0.1 秒固定开销。
- 复现命令：`python scripts/acceptance/cli_backup_restore_e2e.py`
  （默认额外造 32 MB 大文件；`LIUHAO_E2E_BIG_MB=0` 可只跑真实小数据）。

### 关掉程序会丢数据吗

不会。关掉状态窗口只是隐藏到托盘，网关继续在后台运行；用托盘菜单“退出”才结束程序。下次双击快捷方式重新启动，账号、Key、聊天记录都会保留。

## 怎么彻底卸载（卸载默认保留数据）

**程序和数据是分开的**：卸载器只删程序，数据目录单独处理，默认保留（0.1.1+）。

1. 打开 **设置 → 应用 → 已安装的应用**，找到“LiuHao AI OS · 鎏灏智能中枢”，点卸载。
2. 卸载器先删程序，然后问你是否同时删除数据。**默认是“否”**。
3. 想保留账号、Key 和聊天记录：选“否”。以后重装，这些还在。
4. 想彻底删除：选“是”，卸载器还会再确认一次。**两次都确认**才会删除 `data-dir.txt` 记录的数据目录（默认 `D:\LiuHaoData`，或安装时另选的非系统盘目录），删除后无法恢复。
5. 卸载完成后，如果数据目录（默认 `D:\LiuHaoData`）还在，确认不需要后再手动删除。
6. 如果开过开机自启，到 **任务管理器 → 启动** 里确认 `LiuHaoAIOS` / `pythonw.exe` 项已经消失；还在就右键禁用。

一句话记住：**卸载默认会保留数据；只有你明确选了“删除数据”，才会真的删。**
