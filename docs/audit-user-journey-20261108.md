1. **配模型（第 4 停）**：必须懂"Ollama 安装 + ollama pull"或"OpenAI 兼容 base_url + API Key"。产品给了链接和示例，但对没听过这些词的人仍然像天书；没有"先跳过、以后再说"的后果说明（跳过=聊天不可用）。

4. **看结果（第 8 停）**：这不是"看文档能过"的问题——产品自己的详情页同时说"成功创建"和"没有写入任何文件"，用户只能靠不信任来保护自己。

## 六、最该改的三处

### 1. P0：把"成功"绑到真实产物（能力路由 + 验收）

- 现场证据：`在 workspace 下新建 audit-note.txt，写入一行……` 被路由到能力 **"联网调研"**，耗时 2 分 2 秒；评估输出 **"audit-note.txt文件已成功创建……"**；"产生的产物"却是 **"此目标没有向工作区写入任何文件。"**；工作区里没有 `audit-note.txt`（目标 id `cb627b14`）。
- 为什么最该改：这是信任问题，不是体验问题。用户第一次派活就学到"成功不可信"，后面所有能力都会被怀疑。
- 最小改法：
  1. 意图路由对"新建/写入/保存/生成文件"优先匹配文件写入能力，而不是联网调研；
  2. 能力执行必须返回结构化产物（路径 + 大小 + SHA256），没有产物不得进入"成功"；
  3. 评估器只认产物与验收条件，不采信模型自述；
  4. 无产物时状态显示"未完成/未验证"，并明确写出"没有向工作区写入任何文件"作为结论，而不是放在角落里和"成功"并列。
- 验收：同一条指令必须真的在 `workspace` 生成文件且内容匹配；故意不给写权限时必须 failed，且页面任何位置都不出现"成功创建"。

### 2. P1：端口冲突要么自动顺延，要么给 GUI 选择；并修正安装前必读

- 现场证据：8080 被占时启动器直接 FAIL 退出；而 `BEFORE-INSTALL.txt` 第 63 行写的是"端口被占用时会自动顺延，以窗口里打印的『驾驶舱』地址为准"。
- 为什么最该改：8080 是最容易被别的软件占用的端口之一；这是"第二次启动才炸"的问题，用户会认为软件坏了。
- 最小改法：
  1. 启动器探测下一个空闲端口，写回 `current_url`，托盘/浏览器打开实际地址；快捷方式不需要用户改；
  2. 或给一个 GUI 弹窗：`换一个端口（推荐）/ 结束占用进程 / 退出`；
  3. 同步修正 `BEFORE-INSTALL.txt`，不要写未实现的行为。
- 验收：8080 被占时双击快捷方式仍能进入驾驶舱，窗口打印地址与浏览器实际地址一致。

### 3. P1：首启去终端化、去技术噪音

- 现场证据：首启先是 `UnicodeDecodeError` 回溯（`subprocess.py` 的 `_readerthread`，原因是 `about.py` 用 `subprocess.run(text=True)` 读 GBK 输出，而运行时开了 UTF-8 模式）；随后每次启动都有 `Debug API surface ENABLED (APP_ENV=staging)`；建账号成功后打印英文 `set these in the service environment` 与 `Undo with python scripts/register_human_identity.py --revoke`；登录页才说黑窗不能关。
- 为什么最该改：这是每个用户都会遇到的第一印象，而且全部是产品自己制造的噪音，不是环境问题。
- 最小改法：
  1. 默认走 GUI 首启向导（仓库里已有 `scripts/first_run_gui.py`，但 0.1.0 交付包没有它）；
  2. 子进程读取统一加 `encoding="utf-8"` + `errors="replace"`（或按 `locale` 取编码），不再把回溯打到用户屏幕；
  3. 安装版默认 `APP_ENV=production`，或至少不把 `/docs`、`/redoc`、`/openapi.json` 的调试提示打到用户窗口；
  4. 账号创建成功只显示中文"账号已创建，请用此账号登录"；
  5. 提供托盘/最小化，明确"最小化≠关闭服务"。
- 验收：首启无终端窗口、无 traceback、无英文调试行；账号创建后不再出现"set environment"字样；关闭主窗口不会直接停服（或明确提示）。

> 这三处是产品自己造成、且能在一个迭代内修掉的。配模型属于产品定位/商业约束（包内不含模型是既定事实），短期只能靠更好的"帮我装/帮我测/跳过后的明确后果"来缓解，因此不占前三。
