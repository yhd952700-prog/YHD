> 未落地的部分一律标注“未实现”，不使用“规划中”“后续可能”等模糊措辞。

### 1.3 架构边界（不变）

- 同进程模块，**不做独立服务**。
- **不复用**现有 grant 体系，自动化使用独立的确认票据。
- **不引入第二套鉴权体系**：主体身份沿用现有身份内核，只做 `metadata.kind` 判定。
- **不引入** `pyautogui`、`pydirectinput` 或任何传递 GPL 的输入依赖。
- 自动化工具不进入 MCP 投影；MCP 侧只保留现有只读工具。

## 2. 统一抽象（已实现）

四个层次共用同一套契约，后端只负责“观察”和“执行”，安全判定全部在会话层完成。

| 类型 | 位置 | 职责 |
|---|---|---|
| `BackendKind` | `contracts.py` | `fake` / `native` / `browser` / `android`；本轮只有 `fake` 可创建 |
| `TargetScope` | `contracts.py` | `screen` / `window` / `application` |
| `ActionRequest` | `contracts.py` | 一次动作：`action`、`target`、`target_ref`、`params`、`expected_focus`、`step_no` |
| `ActionResult` | `contracts.py` | `executed` / `rejected` / `failed` + 观察 + 错误 |
| `Observation` | `contracts.py` | 焦点、范围、摘要；不含截图明文或输入文本 |
| `AutomationBackend` | `contracts.py` | `observe()` / `execute()` 协议 |
| `Guard` | `guard.py` | 静态规则、频率、熔断 |
| `ConfirmationBroker` | `contracts.py` | 票据签发与单次消费协议 |
| `AutomationSession` | `sessions.py` | 闭环编排与会话状态 |
| `AutomationGate` | `gate.py` | 三重闸判决 |

### 2.1 动作指纹

`ActionRequest.fingerprint()` 只对**动作语义**做稳定哈希：

- 参与：`action`、`target`、`target_ref`、`params`、`expected_focus`。
- 不参与：`session_id`、`step_no`、`principal`。

这样同一个动作在不同会话中指纹一致，而**任何参数变化都会产生新指纹**，旧票据无法复用。
票据再把 `principal + session_id + step_no + fingerprint` 一起绑定，四个维度任一不符即拒绝。

### 2.2 会话闭环

`AutomationSession.execute(plan, ticket)` 的真实顺序：

1. 校验会话状态（`closed` / `frozen` 直接拒绝）。
2. 校验步号必须等于 `当前步号 + 1`。
3. 调用 `backend.observe()` 取得执行前观察。
4. `Guard.check()`：允许清单、禁区、焦点、频率。
5. `ConfirmationBroker.consume()`：原子消费票据。
6. 写入执行前审计（`stage=intent`，`outcome=allow`）。
7. 调用 `backend.execute()`。
8. 成功则清零连续失败；失败则累计，达到阈值冻结会话。
9. 写入执行结果审计（`stage=result`，`outcome=allow|failed`）。
10. 更新步号并返回结果。

`verify(plan, result)` 只做一件事：结果成功，且观察到的焦点符合 `expected_focus`。
更复杂的层内校验（页面内容、设备状态、窗口标题）**未实现**，需要在对应层落地时补充。

## 3. 四层推进路径

四层是**严格串行**的：上一层验收不通过，不进入下一层。每层只允许增加一个
`BackendKind`，且一次会话只能绑定一个后端。

### 第 1 层：浏览器只读

**目标**：让 AI 观察网页内容，但不修改任何远端状态。

- **前置条件**
  - 独立的浏览器配置目录与进程，不复用用户日常登录态。
  - 网络出口受控；不注入 Cookie、令牌或剪贴板内容。
  - 第 1 层实现前，地基测试必须保持全绿（当前 `25 passed`）。
  - 后端类型为 `BackendKind.BROWSER`；**当前未实现**，`create_backend()` 会拒绝创建。

- **允许清单长什么样**
  - `target_ref` 统一为 `browser:<scheme>://<host>/<path>`。
  - 允许清单按 `Guard` 现有语义填写：精确匹配或**尾部 `*` 前缀匹配**，例如
    `browser:https://docs.example.com/*`。
  - 当前 `Guard` 只匹配目标，不区分“读/写”；第 1 层只注册只读动作，动作名白名单**未实现**。
  - 默认允许清单仍为空：未配置时任何浏览器目标都不允许。

- **确认票据怎么让人确认**
  - 设计上，只读动作仍需票据，票据 `preview` 只写“目标站点 + 路径类别 + 动作类别”，
    不写页面正文、查询参数值或表单内容。
  - 人工确认通道**未实现**：当前没有对外注册确认工具，也没有确认 UI。
    票据本身已由 `SqliteConfirmationBroker` 实现，测试直接调用会话 API 完成闭环。
  - 第 1 层落地时必须补一个人类可见的确认面（桌面端或控制台），且只能由
    `metadata.kind=human` 的主体消费票据。

- **审计记什么字段**
  - 事件固定为 `AUTOMATION_ACTION`，范围 `L2`，结果 `allow|deny|failed`。
  - 固定字段：`stage`、`session`（长度 + sha256）、`step_no`、`action`、`target`、
    `target_ref`（长度 + sha256）、`expected_focus`（长度 + sha256）、`action_fingerprint`、
    `params`（逐个参数的摘要）。
  - 页面路径、主机名、查询串一律走 `params` 的哈希化通道，**不写明文 URL 参数**。
  - 页面正文、Cookie、Header、截图内容不进入审计。

- **怎么验证**
  - 已具备：`AuditStore.verify_integrity()` 校验审计链；`session.verify()` 校验焦点。
  - 第 1 层需要新增但**未实现**：抓取内容的摘要与预期摘要比对；只读动作不改变远端状态的复检。
  - 验收要求：同一 URL 连续两次只读，远端状态摘要不变。

- **怎么回滚**
  - 只读本身没有远端副作用，回滚定义为**丢弃本地缓存与摘要**，不保留正文副本。
  - 若发现越权读取，立即 `emergency_stop`，关闭会话并导出审计事件；不做“删除审计”。
  - 页面侧回滚 API **未实现**（也不需要）。

- **明确不做**
  - 不读取需登录后的私密页面；不读取 Cookie、令牌、密码管理器内容。
  - 不规避 robots、付费墙、验证码或访问频率限制。
  - 不上传、不下载文件，不修改任何远端状态。
  - 不接入 MCP 投影。

### 第 2 层：浏览器受控写

**目标**：允许有限、可审计、可人工确认的网页写操作（填写非敏感表单、点击普通按钮）。

- **前置条件**
  - 第 1 层已验收通过，只读观察稳定。
  - 新增**动作级允许清单**（按动作名 + 目标）：当前 `Guard` **未实现**动作级白名单，
    只有目标级允许清单；这是第 2 层必须先补的能力。
  - 每个写动作必须幂等或可检测重复；无法幂等的动作不得进入允许清单。
  - 后端仍为 `BackendKind.BROWSER`（**未实现**）；读/写区分靠策略而非枚举。

- **允许清单长什么样**
  - 目标维度同第 1 层：`browser:https://example.com/forms/*`。
  - 动作维度（待实现）建议形如：
    - 允许：`fill_text`、`select_option`、`click_button`（且目标按钮带语义标签）。
    - 拒绝：`submit_payment`、`delete_account`、`change_password`、`confirm_purchase`。
  - 禁区清单继续生效：密码框、安全界面、终端、系统设置、任务管理器、卸载确认、锁屏。

- **确认票据怎么让人确认**
  - 一次写动作一张票据，`preview` 必须包含：目标站点、动作类别、**将要写入字段的个数**；
    不包含字段值明文。
  - `action_fingerprint` 覆盖所有写入参数，字段值改动必然导致指纹变化，必须重新确认。
  - 人工确认通道**未实现**；确认票据机制已就绪。
  - 票据 TTL 上限 30 秒，过期即拒绝；票据单次消费，重复使用返回 `already_consumed`。

- **审计记什么字段**
  - 复用第 1 层固定字段。
  - 写入内容只记：字段数量、每段文本的长度 + sha256、输入总长度；
    坐标类参数只记归一化值（0–1，四位小数），不记像素绝对值。
  - 表单提交结果、页面跳转目标哈希写入 `params`；不写响应正文。

- **怎么验证**
  - 已具备：票据绑定校验、指纹变化强制重确认、审计链校验、焦点校验。
  - 第 2 层需要新增但**未实现**：提交后的页面状态摘要比对；重复提交检测（幂等键）。

- **怎么回滚**
  - 优先设计“可逆动作”：例如先保存草稿再提交；撤销按钮只允许点击一次。
  - 无逆操作的写动作不得进入允许清单。
  - 真正的业务回滚（删除已提交数据）**未实现**，且不应由自动化模块直接执行；
    应由业务系统提供补偿接口。

- **明确不做**
  - 不处理支付、转账、下单确认、账号删除、密码修改。
  - 不填写密码、验证码、身份证号、银行卡号等敏感字段（禁区清单已覆盖其中一部分）。
  - 不绕过二次验证；不自动点击“同意授权”“安装”“允许”类系统弹窗。
  - 不做批量刷量、抢购、投票等高频写操作。

### 第 3 层：安卓 ADB

**目标**：通过 ADB 对受控设备执行有限操作（启动应用、按键、读取界面层级摘要）。

- **前置条件**
  - 专用测试设备，开启 USB 调试并完成主机授权；不使用 Root、不碰 Bootloader。
  - 固定设备序列号白名单；ADB server 只监听本机。
  - 后端类型为 `BackendKind.ANDROID`；**当前未实现**。
  - 第 1、2 层验收通过；审计链健康。

- **允许清单长什么样**
  - `target_ref` 统一为 `adb:<serial>/<package>`。
  - 允许清单示例：`adb:R58M123ABC/com.example.app`；默认仍为空。
  - 命令类别白名单**未实现**：只允许 `am start`、`input keyevent`、`dumpsys window` 等只读或低风险命令；
    `pm clear`、`wipe`、`root`、`install` 永不进入白名单。

- **确认票据怎么让人确认**
  - 票据绑定设备序列号、包名、命令类别和动作指纹；换设备、换包名、换参数都必须重新确认。
  - `preview` 只写“设备 + 包名 + 命令类别 + 步号”，不写 shell 参数正文。
  - 人工确认通道**未实现**；票据 broker 已就绪。

- **审计记什么字段**
  - 设备序列号、包名、命令类别走哈希摘要；不写完整 shell 命令。
  - 按键码、坐标（归一化）、输入文本长度 + sha256 写入 `params`。
  - 设备返回内容只记长度 + 哈希，不写界面全文。

- **怎么验证**
  - 已具备：票据、指纹、审计链、焦点（在第 3 层应映射为前台包名）。
  - 需要新增但**未实现**：`dumpsys` 前台包名与预期一致；操作后设备状态摘要比对。

- **怎么回滚**
  - 设计方向：`input keyevent KEYCODE_BACK` 返回、`am force-stop <package>` 停止应用。
  - 以上命令**未实现**，且不进入当前代码路径。
  - 设备级不可逆操作（清除数据、卸载、刷机）永久禁止。

- **明确不做**
  - 不 Root、不刷机、不解锁 Bootloader、不关闭安全策略。
  - 不读取短信、通讯录、相册、剪贴板；不自动发送短信或拨号。
  - 不安装/卸载应用，不修改系统设置。
  - 不连接非白名单设备，不使用无线调试暴露到局域网。

### 第 4 层：Windows 桌面键鼠

**目标**：在人类在场的交互式桌面上执行受限键鼠动作（焦点切换、文本输入、普通点击）。

- **前置条件**
  - 交互式、已解锁的桌面会话；无头服务、锁屏、远程断开状态一律拒绝。
  - 人类在场，且急停可用；真实全局热键注册**未实现**，默认会如实上报未注册。
  - 允许清单非空，且只包含明确的应用/窗口标识。
  - 第 1–3 层验收通过；`fake` 后端闭环、票据并发、审计链、熔断、急停测试全部通过。
  - 后端类型为 `BackendKind.NATIVE`；**当前未实现**。

- **允许清单长什么样**
  - `target_ref` 统一为 `app:<process-or-window-id>`，例如 `app:notepad.exe`、`app:chrome|窗口标题摘要`。
  - 允许清单示例：`app:notepad.exe`、`app:excel.exe`；支持尾部 `*` 前缀。
  - 默认空：`Guard(allowlist=())` 时任何目标都被 `allowlist_empty` 拒绝。
  - 禁区清单硬编码覆盖密码框、安全界面、终端、系统设置、任务管理器、卸载确认、锁屏。

- **确认票据怎么让人确认**
  - 一次键鼠动作一张票据；`preview` 只写“应用 + 动作类别 + 步号”，不写输入文本。
  - 输入内容进入指纹但**不进入数据库明文**；票据表只保存 `ticket_id`（令牌 sha256）、
    主体、会话、步号、指纹、预览、状态与时间。
  - 人工确认通道**未实现**：当前没有桌面确认弹窗或控制台确认工具。
  - 第 4 层落地时，确认面必须是系统原生、不可被被测应用遮挡的通道，且只能由人类主体消费。

- **审计记什么字段**
  - 复用固定字段：会话哈希、步号、动作、目标范围、目标标识哈希、预期焦点哈希、指纹、参数摘要。
  - 文本参数：长度 + sha256；坐标：归一化值；组合键：哈希；错误：长度 + sha256。
  - 不写剪贴板内容、不写 OCR 全文、不写窗口截图、不写完整输入明文。
  - 审计写入失败即动作失败：执行前审计失败会阻止后端执行；结果审计失败会向上抛
    `AutomationAuditError`，不吞异常。

- **怎么验证**
  - 已具备：执行前后观察、焦点校验、`session.verify()`、审计链 `verify_integrity()`。
  - 需要新增但**未实现**：窗口标题/进程名复核、目标控件命中复核、动作后界面状态比对。
  - 第 4 层验收必须包含：错误焦点下拒绝、禁区目标拒绝、第 31 个动作被限流、
    连续 3 次失败冻结、票据过期拒绝、审计失败不执行。

- **怎么回滚**
  - 键鼠动作没有通用回滚。设计上只接受“可人工收拾”的动作：
    普通文本输入、非破坏性点击、窗口聚焦。
  - 不提供 `Ctrl+Z` 式自动回滚承诺；**回滚 API 未实现**。
  - 止损手段是：票据 + 急停 + 会话冻结 + 审计留痕。急停触发后取消令牌置位、
    冻结全部会话，并尽力清理 `ctrl/alt/shift/win` 修饰键残留；无清理器时如实上报
    `no_modifier_releaser_configured`，不假装成功。

- **明确不做**
  - 不做密码框、Windows 安全界面、终端、系统设置、任务管理器、卸载确认、锁屏上的任何动作。
  - 不做提权、UAC 自动点击、注册表修改、服务安装、驱动安装。
  - 不读取剪贴板，不做 OCR 全屏采集，不持久化截图。
  - 不使用 `pyautogui` / `pydirectinput`；不引入传递 GPL 的依赖。
  - 不接管浏览器（浏览器走第 1、2 层）和安卓设备（走第 3 层）。

## 4. 三道防线与决策理由

三道防线是分组概念：**上线防线**（三重闸）、**执行防线**（空清单 + 频率 + 熔断 + 票据）、
**止损防线**（急停）。以下只写“为什么这么设”。

### 4.1 上线防线：三重闸（装配闸 / 后端闸 / 主体闸）

三个闸是**独立故障域**，必须同时打开才注册工具：

- `LIUHAO_AUTOMATION_ENABLED`（装配闸）：决定这个部署是否装配自动化能力。
- `LIUHAO_AUTOMATION_BACKEND`（后端闸）：只接受本轮明确支持的后端名；当前仅 `fake`。
- 主体闸：`metadata.kind` 必须是 `human`；`service`、`unknown` 或解析失败一律关闭。

决策理由：

1. **危险能力默认不存在，而不是默认拒绝。** “注册了但拒绝执行”仍会把工具暴露给模型，
   增加误用、提示注入和工具选择干扰；默认不注册，攻击面和认知负担都最小。
2. **三个开关对应三类责任人。** 部署方管装配、开发方管后端实现、安全方管主体类型；
   任何一方未批准，能力就不上线。合并成一个开关会把责任混在一起。
3. **主体闸只认人类。** 服务身份没有“可被追责的人”，无法完成确认票据所要求的
   人类确认语义，因此服务身份不能签发、也不能消费票据。解析身份失败时回落到
   `unknown`（关闭），不是失败开放。
4. **后端闸只认显式支持的名字。** 未实现的后端不会静默降级成 fake；`create_backend()`
   直接抛出 `backend_not_implemented`，避免“以为在跑真实后端、实际在跑假后端”。

### 4.2 执行防线之一：默认空允许清单

`Guard` 的允许清单默认是空元组；空清单直接返回 `allowlist_empty`。

理由：

- 自动化的主要风险不是“动作写错”，而是**目标选错**。白名单比黑名单可靠：
  黑名单永远列不全，白名单列不全的后果只是“不能做”，不是“做错”。
- 允许清单由运维或部署方配置，**不接受模型传入**。`automation.session.open` 固定使用
  `Guard(allowlist=())`，模型无法自行扩大权限。模型能调用工具，不等于模型能改授权。
- 目标标识统一为不透明字符串（`browser:` / `adb:` / `app:`），精确匹配或尾部 `*`
  前缀匹配；不做模糊包含、不做正则，避免匹配歧义带来越权。

### 4.3 执行防线之二：30 动作/分钟

`RATE_LIMIT_MAX_ACTIONS = 30`，窗口 `RATE_LIMIT_WINDOW_SECONDS = 60`，按会话计数。

理由：

- 30/分钟是人可以盯着看并随时急停的节奏；超过这个速度，人类确认会退化成橡皮图章。
- 限制环路失控：模型重试、工作流回环、误判成功后的连续点击，都会在频率上限处被截断。
- 计数在 `record_attempt()` 时发生，只统计**已放行、即将执行**的动作；被票据或守卫拒绝的
  请求不消耗配额，避免拒绝风暴把正常动作挤掉。
- 频率是安全阀，不是性能参数；调高它等于降低人类监督强度。

### 4.4 执行防线之三：连续失败 3 次熔断

`CONSECUTIVE_FAILURE_LIMIT = 3`；达到阈值后 `guard.tripped = True`，会话状态变为 `FROZEN`。

理由：

- 单次失败可能只是焦点漂移、网络抖动；连续 3 次失败更像系统性问题（目标变了、权限丢了、
  前端改版了）。继续重试只会重复产生副作用。
- 熔断后不是“自动恢复”，而是**要求人介入**：冻结会话、新计划被 `session_not_open` 拒绝。
  自动恢复会把一次故障放大成持续故障。
- 成功一次即清零，避免把长时间运行中的偶发失败累计成误熔断。

### 4.5 执行防线之四：TTL ≤30 秒的单次票据

- 票据 TTL 硬上限 30 秒；`issue()` 传入更大值会被钳制，小于 1 秒会被抬到 1 秒。
- 消费使用一条 `UPDATE ... WHERE status='pending' AND expires_at > now` 事务，
  并要求 `rowcount == 1`；并发消费只有一个赢家，其余得到 `already_consumed` 或 `expired`。
- `ticket_id` 存的是随机令牌的 sha256，原始令牌只返回给调用方；数据库被读也无法重放。
- 绑定 `principal + session_id + step_no + action_fingerprint` 四项，任一不符即
  `binding_mismatch`。

理由：

- **确认必须新鲜。** 人对一个动作的同意有时效；30 秒后环境可能已变，旧确认不应继续生效。
- **确认必须一次性。** 重放票据是最容易实现的攻击；单次消费 + 哈希存储直接消除重放面。
- **确认必须绑定具体动作。** 只绑会话不绑指纹，等于给了“这个会话随便做什么”的空白支票；
  参数一变指纹就变，必须重新确认。
- 票据是独立实现，**不复用 grant**：grant 面向资源授权，票据面向“这一次动作的人明确认”，
  生命周期、绑定维度和失败语义都不同，混用会模糊两者边界。

### 4.6 止损防线：急停

已实现：热键候选依次尝试并上报每一次失败；取消令牌（`threading.Event`）；
触发时冻结全部会话；尽力清理修饰键残留并逐键上报失败。
未实现：真实全局热键注册（默认无注册器）。

理由：

- 急停必须**独立于工具总线**。模型卡死、工作流回环、票据通道故障时，人仍要能一键停下；
  因此急停不依赖任何模型调用或确认流程。
- 热键可能被其他软件占用，所以要有备用组合并如实上报；只尝试一个组合、失败了假装成功，
  等于没有急停。
- 急停后必须清理修饰键残留：`ctrl` 卡住会让后续人工操作变形，属于二次伤害。
- 没有注册器时明确返回 `no_hotkey_registrar_configured`，而不是 `registered=True`。
  第 4 层落地前必须补真实注册器，否则第 4 层不得上线。

## 5. 审计与隐私

### 5.1 写入规则

- 一条动作对应一条事件；拒绝、失败也写。事件类型固定 `AUTOMATION_ACTION`，范围 `L2`。
- 成功动作实际产生两条：`stage=intent`（执行前）与 `stage=result`（执行后）。
- 执行前审计失败 → 不执行后端；结果审计失败 → 抛出 `AutomationAuditError`。
  **审计写入失败等于动作失败**，不允许“做完了但没证据”。

### 5.2 哈希规则

- 字符串：`{"len": 长度, "sha256": 摘要}`。
- 坐标：键名为 `x` / `y` / `x_norm` / `y_norm` 且值在 0–1 时，记 `{"normalized": 四位小数}`；
  超出范围记 `{"invalid_coordinate": true}`，不记像素值。
- 列表/集合：`{"items": 数量, "sha256": 整体摘要}`。
- 映射：递归逐项处理。
- 其他类型：转字符串后走长度 + 哈希。

### 5.3 绝不写入

输入明文、剪贴板、OCR 全文、页面正文、窗口截图、Cookie、令牌、密码、完整 URL 查询串、
完整 shell 命令。需要定位时，用哈希关联同一次动作的 intent 与 result。

## 6. 为什么 Windows 侧没有真沙箱，以及为什么真键鼠注入放最后

### 6.1 Windows 桌面没有等同浏览器/安卓的应用级沙箱

- 浏览器有同源策略，安卓有应用沙箱与权限模型；Windows 桌面同用户、同完整性级别的进程
  共享输入队列、窗口焦点、剪贴板和桌面会话。
- UIPI 只阻止低完整性进程向高完整性窗口发送消息，**无法**阻止同级别进程读取屏幕、
  抢占焦点或模拟输入；它不是一个可用的“自动化沙箱”。
- 因此不能承诺“在沙箱里跑键鼠”。只能做**补偿控制**：默认关闭、空允许清单、禁区清单、
  焦点校验、频率上限、熔断、票据、审计、急停。这些控制在第 1–4 层共用，Windows 只是
  风险最高的一层，所以限制最严。

### 6.2 真键鼠注入放最后

1. **副作用不可逆。** 点击、输入、快捷键可能提交、删除、发送；错误焦点下的动作会被
   放大成真实事故。前面三层可以先在可隔离、可复位的环境里验证判定与票据。
2. **观察不可靠。** 屏幕像素、窗口标题、焦点都可能瞬时变化；“看到的”和“以为看到的”
   不一致是键鼠自动化最常见的失败源。必须先用 fake 后端把闭环、审计、熔断、急停跑通。
3. **数据敏感度最高。** 桌面可能同时存在密码框、聊天窗口、邮件、剪贴板。截图与 OCR
   很容易把无关敏感内容带进链路，所以第 4 层只允许最小观察字段，并全面哈希化。
4. **依赖与许可风险。** `pyautogui` 会传递 GPL，`pydirectinput` 同样不可接受。
   引入真实注入前必须先选定可审计、许可干净的实现路径；本轮不引入任何输入依赖。
5. **测试成本最高。** 键鼠后端需要真实交互式桌面、真实窗口和人工在场，无法在 CI 中稳定复现。
   必须等前面的安全地基有测试证据后，再单独安排受控验收。

结论：Windows 真键鼠不是“顺手加上”的能力，而是整套自动化里最后才允许打开的一层。
在真实热键、确认 UI、动作级白名单、窗口复核都未实现之前，第 4 层保持 `NATIVE` 枚举
存在、后端不可创建的状态。

## 7. 验收基线

当前地基的真实验收以以下命令为准（只读、可重复）：

```powershell
.venv\Scripts\python.exe -m pytest tests/test_automation_groundwork.py -q
```

覆盖的断言类别：

- 默认三重关闭时工具列表为空；任一闸关闭仍为空；全开时只有 4 个控制面工具。
- 服务身份不能签发票据；票据过期拒绝；并发消费恰好 1 个成功。
- 参数变化导致指纹变化，旧票据必须重新确认。
- 默认空允许清单拒绝；禁区目标拒绝；焦点不符拒绝；第 31 个动作被限流。
- 连续 3 次失败后会话冻结，新计划被拒绝。
- 急停热键回退与修饰键清理失败逐项上报；急停后执行被拒。
- fake 后端全闭环；审计链 `verify_integrity()` 通过；审计事件中无输入明文与目标明文。
- 审计写入失败时后端未执行（revision 保持 0）。

未验证项（明确列出）：真实浏览器/安卓/Windows 后端、真实全局热键、生产身份解析的
端到端路径、确认 UI、MCP 过滤的独立测试、全量回归。

- 对 `src/ai/tools/kernel_tools.py` 只允许条件追加；对 MCP 投影只允许过滤 `automation.*`；
  对审计只允许新增事件枚举。
