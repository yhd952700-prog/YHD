# SPEC-卡 · 通用内容面（第二季 V4 立卡）

适用范围：发布 dist 里除工作台 / 登录首启 / 设置 / 手机端（各有专卡）之外的
全部内容页——知识中心、提醒、我的文件、办公室、运行总览、待办审批、全部任务
与审计、成员与权限、审批授权、主机命令白名单、能力中心、我的账号与安全、
数据与备份、系统状态与诊断、自改确认、通知中心、关于与隐私等。
双主题共用同一批页面本体，本卡管「所有内容面共同的规矩 + 逐面差异注记」。

## 共同规矩（验收逐条对）

1. **标题属实**：页头大标题与本页内容一致；壳的页名映射缺失时不许落到别的
   页面名上（B1 教训：白名单页曾顶「企业总览」标题）。新页面上线先验标题。
2. **人话面**：用户可见文案不出现开发话——内部路径（`src/…py:符号`）、档位
   代号（A/B/C 档）、机器字段名、原始 API 串（如 `GET /v1/… 返回 N 个节点`)
   一律不进机主信息面；机器字段只进 `title` 悬停或诊断面。
3. **数字属实**：角标、计数、状态必须来自该面自己的真实数据源；开发级信号
   （审计证据链状态等）不进机主数字与信息流（B2/B3 口径）。
4. **空状态单入口**：空列表/未配置时给且只给一个明确下一步动作（大按钮或
   直达链接），不摆多个并列小链接（W8 口径）。
5. **危险操作有门**：删除、恢复、授权类动作必须二次确认或审批门，确认文案
   说清后果；不许一键直达不可逆操作。
6. **失败说人话**：错误提示给「出了什么事 + 怎么办」，不给堆栈、状态码原文
   与内部错误码（错误码可附在诊断面）。
7. **主题与断点**：双主题同内容同结构；手机端按 SPEC-卡-手机端（单列、
   底部导航、抽屉）呈现，不许挤压桌面布局充数。

## 逐面差异注记（只记与共同规矩不同的点）

- **主机命令白名单**：Owner 专属面；标题与副标题以主题层 B1 修复为准
  （「主机命令白名单 / 贾维斯能直接跑哪些主机命令（Owner 专属）」）。
- **运行总览**（原「企业总览」改名，V1.5）：页内不得出现原始 API 返回串
  （W1 修复口径）；改名只动显示名，导航目标不变。
- **通知中心**：与铃铛的双数据源是已知缺陷，统一方案 = A3 回植清单 §二
  （`docs/frontend-a3-backlog.md`），在 A3 落地前以 B2/B3 缓解口径为准。
- **能力中心**：说明默认折叠一行；档位以人话标签呈现（「能操控电脑」等，
  W9 口径）；技能包管理（V7）自本面进入，包格式规格见
  `docs/skill-package-format.md`。
- **知识中心**：本地语义引擎未下载/未就绪时必须如实显示状态与原因（V6
  口径）；模型下载入口是 A3 回植项（清单 §四），未落地前不许摆假入口。
- **我的账号与安全**：常驻恢复码说明卡（§5-8 口径，主题层 `fixAccount`）。
- **关于与隐私**：承接「下载 Windows 桌面版」入口（V4 落地，主题层
  `fixAbout`，与登录页下载链同址）；版本行显示产品版本与提交号属实。
- **数据与备份**：云备份（V10）在本面暂无面板（A3 回植项，清单 §五）；
  本机备份与快照的分工文案以 V10 工具描述口径为准，不许混称。
- **系统状态与诊断**：开发级信号的合法去处——审计证据链、机器字段、原始
  日志都只许出现在这里，不受规矩 2/3 限制（本面即诊断面）。
