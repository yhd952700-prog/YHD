# 用户故障处置手册（v0.1.1）

> **只读整理**：本次未改动任何代码或配置。用户原话逐字取自源码；日志关键词取自代码里的 `logger` 调用；未在真机逐条复跑，凡属推演会标「推断」。
> **排序原则**：按「用户实际会撞上的概率」从高到低，不按字母、不按模块。
> **三条线**：每条只写三行 —— 看到什么 → 怎么处理（≤3 步） → 还不行看哪、何时必须找作者。
> **原文口径**：下文引用的界面文字与日志原文以当前版本 0.1.1 的代码为准；如果你看到的不是这句，请截图反馈。

---

## 0. 60 秒定位：先认日志

数据目录默认 `D:\LiuHaoData`，回退 `%LOCALAPPDATA%\LiuHao\data`；以 `<程序目录>\data-dir.txt` 为准（程序目录默认 `D:\LiuHao`）。

| 日志 | 位置 | 搜什么 |
|---|---|---|
| 启动器 | `<数据目录>\logs\launcher.log` | `[FAIL]`、`数据目录不可写`、`[warn] 无法写入启动日志` |
| 网关崩溃堆栈 | `<数据目录>\logs\desktop-gateway.log` | `Traceback`（看最后一行） |
| 业务主日志 | `<数据目录>\logs\liuhao.log` | `upstream HTTP failure status=`、`kind=`、`account.` |
| 结构化错误 | `<数据目录>\logs\error.log` | `evt=llm.call.failed`、`error_class=`、`errno=`、`key_fp=` |
| 桌面壳 | `<数据目录>\logs\desktop.log` | `启动门结论`、`系统托盘未启动`、`instance.lock` |
| 引导兜底 | `<程序目录>\bootstrap.log`（启动器/桌面壳失败）；`%LOCALAPPDATA%\LiuHao\logs\bootstrap.log`（网关引导阶段失败，数据目录不可解析时还会落到 `%TEMP%`） | 两个位置都看；数据目录/日志目录都写不进去时，这里是唯一记录 |

**`error.log` 为空不代表正常**：它是 ERROR 级专用；模型类失败有的只写 INFO 到 `liuhao.log`。
**`config\current_url.txt` 不是权威地址**：它只是 `scripts/start_liuhao.py` 某次启动成功时写下的快照（安装版 `LiuHao.bat` 启动会写，双击桌面图标启动不写，源码 `start-liuhao.bat` 默认也不写），可能是旧端口/死 pid。地址一律以状态窗口「控制台：」为准。
**一键证据**：控制台「系统设置 → 遇到问题 → 一键诊断包 → 导出诊断包」；命令行则在**程序目录**运行
`runtime\python.exe -m src.desktop diagnose`（源码仓库用 `.venv\Scripts\python.exe -m src.desktop diagnose`）。

### 打不开怎么办：六类对号（与「一键诊断包」的检查项一一对应）

启动后打不开控制台，先按这六类对号。**每一类都有明确的日志字段**，不要凭感觉猜网络；
诊断包里 `diagnosis.json` 的部分 `id` / `title` 就是下面这六类（另有“安装文件完整性”“运行时缺失”两项，见场景 20）。

| # | 诊断包 check（`id` / 标题） | 先看哪个日志、搜什么 | 对号场景 | 处置要点 |
|---|---|---|---|---|
| 1 | `port_conflict` / 端口被占用 | `launcher.log` 搜 `已被占用`、`evt=port.conflict`；`desktop.log` 搜 `evt=port.`（看用户选了哪种处理办法）；诊断包 `ports.json` 的 `port_conflicts`（含占用者 PID / 程序名） | 场景 2 | 有桌面时窗口二选一：**关掉占用程序再试** / **换一个端口继续**（原地重启，不用关窗）；纯命令行看「处理一／处理二」，**返回码 2 = 未启动** |
| 2 | `directory_not_writable` / 数据目录 / 日志目录不可写 | `launcher.log` 搜 `数据目录不可写`、`[warn] 无法写入启动日志`；诊断包 `installation.json` 的 `data_dir_write_probe` / `logs_dir_write_probe` | 场景 12 | 腾出 ≥2 GB、取消只读、关掉同步盘/杀软扫描；换普通本地盘仍不可写 → **联系作者** |
| 3 | `model_key_invalid` / 模型 Key 无效 | `liuhao.log` 搜 `status=401 kind=invalid_key`；`error.log` 搜 `evt=llm.call.failed` 与 `key_fp=` | 场景 3 | 删掉重填整段 Key → 点「测试连接」；确认接口地址与厂商匹配（DeepSeek 用 `https://api.deepseek.com/v1`） |
| 4 | `model_network_unreachable` / 模型服务网络不通 | `error.log` 搜 `evt=llm.call.failed`，看 `error_class=` 与 `errno=`；诊断包 `model_health.json` 的 `endpoints` | 场景 4 | **按 `error_class` 分三种，不要笼统「检查网络」**：<br>`ConnectionRefused`→`errno=10061`：端点没在监听，查地址/端口或 Ollama 是否在跑；<br>`DNSFailure`→`errno=11001`：域名解析失败，查 base_url 与代理 DNS；<br>`Timeout`→`errno=10060`：被代理/防火墙/上游拖住，先关全局代理再试 |
| 5 | `database_corrupt` / 数据库文件损坏 | `desktop-gateway.log` 搜 `Traceback`；诊断包 `db_check.json` 里 `result=failed`（`quick_check` 未通过） | 场景 1（启动即崩）；暂无独立场景，以 `db_check.json` 为准 | **先退出程序并整目录备份**，再把损坏的 `.db` / `.sqlite3` 改名或移走，重启会自动重建空库；**不要直接删数据目录**，拿不准先联系作者 |
| 6 | `console_assets_missing` / 静态资源缺失（白屏） | `liuhao.log` 搜静态资源 404；诊断包 `static_assets.json` 的 `missing`；程序目录 `console\dist` 是否存在 | 场景 24 | `Ctrl+F5` 强刷 → 注销 Service Worker → 覆盖安装补齐 `console\dist` |

> 六类里只有第 4 类要看网络，且必须按 `error_class` 分三种；日志已有 `errno=` 时，不要再让用户「检查一下网络」了事。
> 第 1/2/5/6 类与模型无关，改 Key、换模型不会解决；第 3 类才是 Key 的问题。

## 一、按最可能发生排序的 24 个场景

### 1. 服务没起来：状态窗口报「启动失败」，或一直停在「正在启动」
- **看到**：状态窗口显示「网关进程在启动过程中退出」/「等待 120s 仍未就绪（最后阶段：…）」，托盘图标是红色或根本没有图标；`launcher.log` 里是 `[FAIL] 网关进程在启动过程中退出。日志：…；诊断包：…` 或 `[FAIL] 等待 120s 仍未就绪（最后阶段：…）` → 含义：真正干活的 Python 网关崩了或卡住，不是浏览器问题。
- **处置**：① 看状态窗口停在的错误原因（关掉窗口只是隐藏到托盘，不会停掉排障线索）；② 打开 `<数据目录>\logs\launcher.log` 搜 `[FAIL]`；③ 用托盘菜单“退出”后重新双击桌面图标，仍失败就导出诊断包。
- **还不行**：`logs\desktop-gateway.log` 搜 `Traceback`，最后一行即根因；若 `runtime\python.exe` 缺失或被杀软隔离 → **联系作者**。

### 2. 端口被占：`端口 8080 已被占用`
- **看到**：`网关端口 8080 已被占用（占用者：PID … 程序名，程序路径）。为避免地址变化，启动器不会自动换端口。` → 含义：8080 被别的进程（常见是上次没退干净的鎏灏）占住；程序**不会悄悄换端口**，避免地址漂移。占用者查不到时写「查不到（可能需要管理员权限才能看到占用该端口的程序）」，不会留空白。
- **有桌面时**：会弹「鎏灏：网关端口被占用」窗口，二选一 —— **关掉占用程序再试**（先关掉上面这个程序（或重启电脑），再点它，程序会原地继续启动；仍被占就再次弹出）或 **换一个端口继续**（填一个空闲端口（例如 8081），校验空闲后直接继续启动，**不用重开窗口**）。关掉这个窗口等同「稍后再处理」，状态窗口里的「重新启动服务」会再次给出这两个选项。之后地址变成 `http://127.0.0.1:<端口>`，以状态窗口显示的「控制台」地址为准。
- **纯命令行 / 无桌面时**：不弹窗，逐行打印「处理一」「处理二」—— 处理一是关掉占用进程后重跑；处理二是**复制「处理二」下面那整条命令（含引号）**重跑，命令里已写好一个候选端口（通常是 8081）。**返回码 2 = 没有启动**（端口冲突等预检失败），不是安装损坏，按提示处理后重跑即可。
- **还不行**：`launcher.log` 搜 `已被占用`、`evt=port.conflict`；`desktop.log` 搜 `evt=port.retry` / `evt=port.switch` / `evt=port.deferred`，看占用者 PID 和用户选了哪种处理办法；同一进程每次开机都抢 8080（系统组件/安全软件）→ **联系作者**。

### 3. Key 无效：聊天只回「…返回 HTTP 401」
- **看到**：`<服务商名>返回 HTTP 401，详情已记录到服务端日志。`（例如 `DeepSeek返回 HTTP 401，详情已记录到服务端日志。`）→ 含义：Key 填错、复制不全、被吊销、或该 Key 不属于这个接口地址；**不是**额度问题。
- **处置**：① 「系统设置 → 模型管理」删掉重填 Key（整段粘贴，别带空格/引号）；② 点「测试连接」，正常应显示 `连接成功（… ms）`；失败会显示 `API Key 无效或没有权限。请检查 Key 是否填错、是否复制完整；建议重新生成后再试。`；③ 确认接口地址与该厂商匹配（DeepSeek 用 `https://api.deepseek.com/v1`）。
- **还不行**：`liuhao.log` 搜 `status=401 kind=invalid_key`；`error.log` 搜 `evt=llm.call.failed` 与 `status=401`，核对 `key_fp=` 是否是你刚填的 Key；Key 在厂商控制台可用但仍 401 且无代理 → **联系作者**。

### 4. 连不上模型服务（端点不可达 / 代理 / 公司网络）
- **看到**：`连不上模型服务。请检查网络和「系统设置 → 模型管理」里的接口地址后重试。` 或 `这次没有拿到回复，请稍后再试。…` → 含义：请求根本没到厂商，被 DNS、代理、TLS 或防火墙断了。
- **处置**：① 浏览器打开厂商控制台，确认这台机器能上网；② 关掉系统代理/公司 VPN 的「全局代理」再试（`http_proxy` 拦 `127.0.0.1` 是本机第一大坑）；③ 本机 Ollama 用户确认 `ollama serve` 在跑、地址是 `http://127.0.0.1:11434`。
- **还不行**：`error.log` 搜 `evt=llm.call.failed`，看 `error_class=`：`ConnectionRefused`→`errno=10061`、`DNSFailure`→`11001`、`Timeout`→`10060`，并核对 `host/port`；内网强制 TLS 拦截（杀软/上网行为管理）且改不了 → **联系作者**。

### 4.1 证书校验失败（自签证书 / 公司代理 / 私有 CA）
- **看到**：`无法验证模型服务的证书（自签证书、私有 CA 或公司代理）。本产品不同链路的证书信任来源不同（有的读取系统证书商店，有的只用内置证书列表），在系统里「信任该证书」不一定生效。请改用可直连的网络或地址；若必须走公司代理，请联系网络管理员提供受信任的 HTTPS 入口。`
  变体：`证书与访问地址不匹配…`（域名/host 对不上）、`证书已过期（也可能是本机时间不正确）…`、`证书尚未生效…`。
  测试连接里对应 `reason`：`certificate_untrusted` / `certificate_hostname` / `certificate_expired` / `certificate_not_yet_valid` / `certificate`（兜底）。
- **含义**：HTTPS 握手的证书链没通过校验。常见来源：公司上网行为管理/杀软做了 TLS 中间人、内网自建网关用自签证书、本机时间不对。
- **处置**：
  ① 先核对系统时间（右下角日期、时区），时间错会导致"已过期/尚未生效"；
  ② 能换网络就先换（手机热点可直连时，说明是公司代理的问题）；
  ③ 域名不匹配：核对「模型管理」里的接口地址，别把 IP 填进只签了域名的地址；
  ④ 必须走公司代理时，让网络管理员提供代理的根证书 PEM 文件，按下面任选一种方式交给本产品（**不需要重启服务以外的东西**，改完重启网关生效）。
- **信任来源分叉（排障要点）**：本产品不同链路读的信任库不同——
  - OpenAI / Anthropic / Google 等走 `httpx`：默认加载 Windows「受信任的根证书颁发机构」，并识别环境变量 `SSL_CERT_FILE`；
  - Ollama / Moonshot / DeepSeek 等走 `requests`：只认内置证书列表（certifi），会识别 `REQUESTS_CA_BUNDLE`。
  所以"在系统里信任证书"对第一条链路可能生效、对第二条链路一定不生效，界面不会替用户断言其中一种。
- **把手上的根证书交给两条链路**（PowerShell，先启动一个长期生效的会话，或在启动器里设置）：

  ```powershell
  # 公司代理根证书，例如 C:\certs\corp-proxy-root.pem
  [Environment]::SetEnvironmentVariable('SSL_CERT_FILE', 'C:\certs\corp-proxy-root.pem', 'User')
  [Environment]::SetEnvironmentVariable('REQUESTS_CA_BUNDLE', 'C:\certs\corp-proxy-root.pem', 'User')
  ```

  `SSL_CERT_FILE` 是**替换**默认文件路径（Windows 下系统商店仍参与校验），`REQUESTS_CA_BUNDLE` 是 requests 的 CA 包。设完要重启网关（关掉桌面窗口重新打开）。
- **安全提醒**：把公司代理根证书加进信任列表，等于同意"该代理可以解密本机到模型服务的流量"——其中包含 API Key 与对话内容。只在你能确认这台代理由公司网络团队管理时这样做；公共/不明来源的代理证书不要装。
- **还不行**：`error.log` 搜 `evt=llm.call.failed`，`error_class=APIConnectionError` 且下一行是 `SSLCertVerificationError` / `certificate verify failed: ...`，按括号里的原因（`unable to get local issuer certificate` / `self-signed certificate in certificate chain` / `Hostname mismatch` / `certificate has expired`）对照上面处置；`model probe failed` 行会给出同一分类。技术原文只写日志与诊断包，界面不展示。

### 5. 额度用完 / 被限流
- **看到**：`模型账户的额度或余额不足，请到提供方控制台充值后重试。` 或 `请求被上游限流（短时间内调用过多），请稍后重试。` → 含义：Key 本身有效，账户余额见底，或短时间请求太多。
- **处置**：① 去厂商控制台看余额/额度；② 充值或换一个 Key；③ 限流则等 1 分钟再发一条。
- **还不行**：`liuhao.log` 搜 `kind=quota_exhausted` / `kind=rate_limited`；刚充值仍报额度耗尽（厂商计费延迟或 Key 绑了别的项目）→ 找厂商；反复限流但用量很小 → **联系作者**。

### 6. Key 被封 / 吊销
- **看到**：聊天里是 `API Key 无效或已失效，请到「系统设置 → 模型管理」更新密钥。`；日志里 `kind=key_revoked` → 含义：厂商侧把 Key 停用（欠费、泄露风控、手动禁用）。测试连接会显示 `API Key 已被提供方停用或吊销。请到提供方控制台重新生成 Key，再填到这里。`
- **处置**：① 去厂商控制台看该 Key 状态；② 新建一个 Key 并替换；③ 若怀疑泄露，先删旧 Key 再换。
- **还不行**：`liuhao.log` 搜 `kind=key_revoked`；新 Key 仍被立即吊销且本机无异常请求 → 查厂商风控通知，必要时**联系作者**排查是否有异常调用。

### 7. 模型名不存在
- **看到**：聊天里是 `模型不存在或已下线，请核对模型名（可点「测试连接」查看服务端返回）。`；测试连接是 `模型名不存在，或该接口地址不支持这个模型。请核对模型名称后重试。` → 含义：填的模型 ID 厂商没有，或该账号没开通。
- **处置**：① 打开厂商文档抄准模型 ID（如 `deepseek-chat`，区分大小写和 `-`）；② 回「模型管理」重新选/填并保存；③ 点「测试连接」确认。
- **还不行**：`liuhao.log` 搜 `status=404 kind=model_not_found`；模型 ID 确认无误、厂商文档也这么写 → **联系作者**。

### 8. 忘记密码，但还留着恢复码
- **看到**：登录页「忘记密码」→ 输入恢复码 → 若失败显示 `恢复码无效或已失效。` → 含义：恢复码一次性，用过就作废；或不是这台机器生成的。
- **处置**：① 用**没被用过**的恢复码，逐字复制（区分 `0/O`、`1/l`）；② 必须在这台机器上操作；③ 重置后立刻登录，在「恢复码」页生成一枚新码并抄到纸上。
- **还不行**：恢复码确实没用过仍报无效 → 看 `liuhao.log` 搜 `account.recovery`；仍无解 → **联系作者**，别反复试（会触发锁定）。

### 9. 密码输错太多次被锁
- **看到**：`登录失败次数过多，请在 N 秒后重试` → 含义：同一账号短时间失败 5 次，进入冷却，不是账号被封。
- **处置**：① 停手等倒计时结束；② 确认键盘大写/输入法，再输一次；③ 忘了就按第 8 条走恢复码。
- **还不行**：冷却结束后正确密码仍 `账号或密码不正确` → `liuhao.log` 搜 `account.login`；怀疑账号被改 → **联系作者**。

### 10. 消息太长 / 上下文超长
- **看到**：`消息过长或格式不合法：单条消息最多 8000 字，请精简或分段发送`（422）；或长对话后回 `模型服务返回 HTTP 400，详情已记录到服务端日志。` → 含义：单条超 8000 字，或整段上下文超过模型窗口。
- **处置**：① 把长文拆成几条发；② 新建一个会话再问（旧会话上下文会累积）；③ 换上下文窗口更大的模型。
- **还不行**：`liuhao.log` 搜 `status=400 kind=upstream_error`；**注意日志里看不到 `context_length_exceeded` 原文**（上游正文被脱敏丢弃），只能靠「换新会话就好了」来确认；新会话发一句「你好」仍 400 → **联系作者**。

### 11. 流式中断：回复到一半停住
- **看到**：文字停止增长，末尾出现 `这一轮没有成功，请稍后重试。` 或 `这次没有拿到回复，请稍后再试。…` → 含义：连接被中断（网络抖动、代理掐断长连接、上游超时）。
- **处置**：① 直接重发这条消息；② 关掉代理/VPN 再试；③ 换短一点的提问，减少生成时长。
- **还不行**：`error.log` 搜 `evt=llm.call.failed` 看 `duration_ms=` 与 `error_class=Timeout`；每次都在同一时长（如 30/60 秒）断 → 超时设置问题，**联系作者**调大超时。

### 12. 数据目录不可写 / 磁盘满
- **看到**：`无法写入「…」：写入失败（常见原因：磁盘已满、数据目录只读或文件被占用）…`，启动期则是 `数据目录不可写：… 请换一个位置，或确认磁盘没有写满。` → 含义：写盘失败，历史数据一般不丢。
- **处置**：① 看该盘剩余空间，清出至少 2 GB；② 关掉可能占用该目录的程序（同步盘、杀软扫描、另一个鎏灏）；③ 右键数据目录 → 属性，取消「只读」。
- **还不行**：`launcher.log` 搜 `数据目录不可写` 与 `[warn] 无法写入启动日志`；换到 `D:\LiuHaoData` 这类普通本地盘仍报不可写（权限/组策略/加密盘）→ **联系作者**。

### 13. 托盘图标消失
- **看到**：窗口标题附近 `托盘：不可用（…）`，或 `desktop.log` 里 `系统托盘未启动：…` → 含义：托盘创建失败（资源管理器重启、pystray 异常），网关通常还在跑。
- **处置**：① 先看任务栏「隐藏的图标」里是不是被折叠了，拖出来；② 重启资源管理器（任务管理器 → 重新启动 Windows 资源管理器）；③ 关掉鎏灏重新双击图标。
- **还不行**：`desktop.log` 搜 `系统托盘未启动`；每次都失败且网关正常 → 直接用浏览器开 `http://127.0.0.1:8080` 顶着用，并**联系作者**。

### 14. 双开：提示「鎏灏已经在运行」
- **看到**：`鎏灏已经在运行。请使用任务栏通知区（托盘）的图标打开窗口或控制台。` → 含义：实例锁生效，防止两个进程抢同一份数据。
- **处置**：① 点托盘图标 / 任务栏里已有的窗口；② 找不到窗口就任务管理器结束残留的 `python.exe`（确认是鎏灏的）；③ 再双击图标。
- **还不行**：进程已全关仍报占用 → 删 `<数据目录>\run\instance.lock` 后重启（先确认没有鎏灏在跑）；锁文件反复残留 → **联系作者**。

### 15. 备份导入失败
- **看到**：`本机已完成初始化，备份包只能在全新实例上导入，不能覆盖现有数据` / `凭据包无效或口令错误` / `该备份包已被导入，出于安全原因不能重复使用` / `目标机存储空间不足…` → 含义：导入只允许在**全新实例**、且同一包只能成功一次。
- **处置**：① 确认目标机还没建过账号（已建就只能先卸载并删除数据再装）；② 口令逐字重输，注意全角/半角；③ 腾出空间后重试同一个包。
- **还不行**：包从没成功导入过却提示「已被导入」→ 记下时间，**联系作者**；连续 5 次失败会锁定，需稍后或换包。

### 16. 升级后版本没变 / 数据没迁移
- **看到**：`已安装…请关闭并重新启动鎏灏，重启后版本才会变成新版本。` 或 `未配置更新源（本地发布目录或 HTTP 清单），无法检查更新` → 含义：升级已装但没重启，或安装者没配更新源。
- **处置**：① **完全退出**鎏灏（含托盘）再启动，版本才会切；② 没配更新源就找安装者要本地发布目录；③ 升级后数据应在原数据目录，先别改路径。
- **还不行**：看 `<数据目录>\upgrade-state\status.json` 的 `phase` 与 `labs\upgrade-backups`；出现 `自动回滚失败：…`，或版本变了但数据缺失 → **立刻停手、联系作者**（回滚备份在 `upgrade-backups`）。

### 17. 没有恢复码，本机生成也失败
- **看到**：`无法在本机生成恢复码。请改用你保存过的备份恢复，或联系设备管理员协助重置密码。` 或 `本机恢复流程还需要桌面端的一次性证明：请从鎏灏桌面窗口点“打开控制台”…` → 含义：只能从桌面端走本机证明，浏览器直连不算本机。
- **处置**：① 从**桌面窗口**点「打开控制台」再进恢复页；② 确认数据目录没被改（本机证明按机器绑定）；③ 成功后立刻抄下只显示一次的恢复码。
- **还不行**：已从桌面窗口进入仍要证明，或提示 `已存在有效的恢复码` 但你找不到 → **联系作者**，不要删数据目录。

### 18. 恢复码丢了 + 要换机器
- **口径**：换机**只认带口令的备份包**。不要直接把整个数据目录拷到新电脑，也不要在同一台电脑换 Windows 用户后继续用旧目录——模型主密钥、身份签名密钥、JWT 签名密钥都用 DPAPI 绑定在原电脑/原用户上。拷过去启动会看到 `本机密钥无法在此机器解密，请用账号备份包恢复或重新生成。`，程序保留原密文、不覆盖，但模型 Key 解不开、登录签名不可信。直接拷目录属于**不支持场景**。
- **看到**：登录页 `恢复码无效或已失效。`，且手上没有可用码 → 含义：恢复码一次性，**备份包里也不含恢复码**；但备份包带着登录凭据哈希，**记得原密码就能直接登录**，恢复码只在忘记密码时才需要。
- **处置**：① 记得原密码：新机全新安装 → 导入备份 → 用**原来的账号和密码**登录，不需要恢复码；② 忘了密码：找回当初抄下的恢复码（纸/密码管理器），导入后用它在登录页重置密码；③ 恢复码也找不到：登录后立刻到左侧「恢复码」页生成一枚新的并保存。
- **还不行**：原密码和恢复码都没有，本机数据还在 → 只能在本机登录后重新导出；本机也进不去 → **联系作者**（这是唯一需要人工介入的账号场景）。

### 19. 开机自启失效
- **看到**：开机后没有托盘、也没有窗口；`autostart status` 报 `找不到桌面入口 … 请重装或从完整目录登记自启。` → 含义：注册表自启项丢失，或指向了已删除的路径。**默认是关闭的**。
- **处置**：① 命令行跑 `python -m src.desktop autostart status` 看是否 `enabled`；② 跑 `autostart enable` 重新登记；③ 重启一次验证。
- **还不行**：`status` 显示 enabled 但开机仍不启动（被安全软件拦注册表/启动项）→ `desktop.log` 搜 `autostart`；放行后仍无效 → **联系作者**。

### 20. 杀毒软件拦截 / 安装文件不完整
- **看到**：`[FAIL] 安装文件不完整：缺少 runtime\python.exe，程序无法启动。` 或 `请重新安装或修复安装` → 含义：`runtime` 被隔离/删除，或安装被中断。
- **处置**：① 打开杀软「隔离区」，把 `D:\LiuHao` 整个目录加白名单并恢复文件；② 重新运行安装包做修复安装；③ 再启动。
- **还不行**：看 `bootstrap.log` 与安装目录下 `runtime\python.exe` 是否真的存在；加白名单后仍被反复隔离（企业统一管控）→ **联系作者**要免安装排查方案。

### 21. 安装被中断 / 覆盖安装失败
- **看到**：安装到一半报错退出；或覆盖安装后旧程序还在跑、文件被占用 → 含义：安装器**不会**自动关闭旧鎏灏（`CloseApplications=no`），文件占用导致覆盖失败。
- **处置**：① 托盘右键退出 + 任务管理器确认没有 `python.exe`/`pythonw.exe`；② 重新运行安装包（同目录覆盖即可，默认保留数据）；③ 仍失败就重启电脑后再装。
- **还不行**：看 `%TEMP%\Setup Log *.txt` 搜 `Error` 或 `Access denied`；提示文件被占用的具体路径 → 先手动解锁，仍失败 → **联系作者**。

### 22. 路径含中文空格 / 路径太长
- **看到**：`安装路径过长：… 已超过 Windows 的 260 个字符上限，安装会在中途失败。请改选更短的目录…` 或 `安装目录不可写：…` → 含义：路径超过 260 字符或落在受限目录。
- **处置**：① 安装目录保持短路径如 `D:\LiuHao`；② 数据目录用 `D:\LiuHaoData`（**不要**放在程序目录里，升级会覆盖）；③ 路径里有空格/中文本身可用，但别叠加超长层级。
- **还不行**：换到 `D:\LiuHao` 仍报不可写（无 D 盘会自动回退 `%LOCALAPPDATA%\Programs\LiuHao`）→ 检查盘符是否存在/可移动盘 → **联系作者**。

### 23. 手机 / 局域网访问被防火墙拦
- **看到**：电脑上能开，手机浏览器一直转圈/超时 → 含义：网关只绑了 `127.0.0.1`，或 Windows 防火墙没放行。
- **处置**：① 用 `--host 0.0.0.0` 启动（默认只允许本机）；② 手机与电脑连同一 Wi-Fi；③ 防火墙允许 Python 的**专用网络**入站，或按 `firewall.py` 提示执行 `New-NetFirewallRule`。
- **还不行**：把当前网络类型改为「专用网络」再试；公司 Wi-Fi 隔离了终端互访（AP isolation）→ 换手机热点验证，仍不通 → **联系作者**。

### 24. 诊断包导出失败 / 打开是白屏
- **看到**：`诊断包自检失败，已删除产物：…`；或浏览器只显示空白页 → 含义：要么写盘失败，要么前端构建产物缺失。
- **处置**：① 先确认数据目录可写（见第 12 条），再导出；② 白屏按 `Ctrl+F5` 强刷，仍白看 `logs\liuhao.log` 有无静态资源 404；③ 重新安装覆盖修复前端产物。
- **还不行**：`diagnose` 持续自检失败；或安装目录缺 `console\dist` → **联系作者**。

### 25. 预算超限（402）/ 权限不足（403）
- **看到**：聊天、管家派活、员工执行或目标执行时提示 `本次调用会超出可用预算（按保守 token 估算），请调整额度或换更便宜的模型。`，HTTP 状态 **402**、`code=budget_exceeded`；或提示 `权限不足：当前账号没有被授权执行这个操作。`，HTTP 状态 **403**、`code=permission_denied`。→ 含义：**402 是钱/额度不够，不是没权限；403 才是这个账号真的没有这项权限。** 两者都刻意使用不同的状态码和 `code`，响应体与响应头都带 `correlation_id`，可在审计页对上同一条 `ACCESS_DENIED`。流式请求同样在**建流前**返回 402/403（响应不是 `text/event-stream`，没有任何分块输出）；只有建流之后才发生的兜底拒绝（例如等会话锁期间额度被别的会话用光）才出现在 `done` 帧的 `status=denied` + `reason`。
- **处置**：① 402：点提示里的「去用量页调整额度」到「我的 Key → 用量」提高额度，或点「换更便宜的模型」到「系统设置 → 模型管理」换一个已定价、更便宜的模型；② 403：换用有该权限的账号（根账号或被授权的成员），或让上级账号授权后重新登录再试；③ 记住口径：**未定价模型只统计用量、不参与预算拦截**——不会因为"成本未知"被当成 0 元放行，也不会因为没有价格表就把人挡在门外。
- **还不行**：`liuhao.log` 搜 `budget_exceeded` / `permission_denied`，拒绝日志带 `phase=pre_stream`（建流前）或 `phase=during_stream`（流中兜底）；再用 `correlation_id` 在「审计」页筛 `ACCESS_DENIED`，核对 `reason`、`estimated_cost`、`available`；额度确实够、也确认有权限却仍 402/403 → **联系作者**。

## 三、什么情况必须联系作者（硬条件）

1. 换到普通本地盘（如 `D:\LiuHaoData`）、磁盘充足、目录非只读，仍报「数据目录不可写」。
2. 8080 被系统组件或安全软件长期占用，且每个版本/每次开机都冲突。
3. 杀软加白名单后仍反复隔离 `runtime\python.exe`。
4. Key 在厂商控制台确认有效，本机无代理，仍稳定返回 401/403。
5. 新开会话、只发一句「你好」仍返回 400（排除上下文超长）。
6. 恢复码、备份包、本机生成恢复码三路全部失败。
7. 备份包从未成功导入，却提示「该备份包已被导入」。
8. 升级出现「自动回滚失败」，或版本变了但数据缺失。
9. `autostart status` 为 enabled，开机仍不启动。
10. 一键诊断包持续「自检失败」；或 SQLite 完整性校验报错。
