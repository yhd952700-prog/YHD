# 使用指南（Windows 安装版）

> 本页描述 **0.1.1 及以上版本**的真实行为；旧版本请先升级。0.1.0 的包只有命令行向导（黑窗口问答），不要按本页的图形窗口操作，差异见 [END-USER-GUIDE.md](END-USER-GUIDE.md) 开头。
>
> **版本口径**：源码与安装包为 `0.2.1`（单机自用，不对外发布）。文中「0.1.1+」只表示「从 0.1.1 开始就有的能力」，之后的版本同样适用。

## 一、首次启动

双击桌面快捷方式（程序默认装到 `D:\LiuHao`，D 盘不可用时为
`%LOCALAPPDATA%\Programs\LiuHao`）。需要命令行模式（排障用）时，在程序目录运行
`LiuHao.bat --console`；源码仓库用 `scripts\start_liuhao.py`。

1. 出现「LiuHao AI OS · 鎏灏智能中枢」状态窗口，里面是「网关：」「启动：」「健康：」「控制台：」几行，
   状态从“正在启动…”变为“运行中”；任务栏通知区（托盘）同时出现鎏灏图标。**这个窗口不需要输入任何内容。**
2. 同时弹出标题为 **「鎏灏首次设置」** 的窗口（仅当机器上还没有可登录身份时出现），
   底部按钮是 **上一步 / 取消 / 下一步**，共五步（第 4 页是「完成前请确认」，第 5 页是「自检结果」）：
   - **第 1 步 · 数据目录**：默认 `D:\LiuHaoData`，一般不用改；点 **浏览…** 可以换位置。
   - **第 2 步 · 管理员账号**：**账号（英文）**、**显示名（可中文）**、
     **登录密码 / 确认密码**（至少 8 位，且同时包含字母和数字）。密码只存 PBKDF2 哈希在
     `config\auth_secrets.json`，不存明文。
   - **第 3 步 · 选择模型（可跳过）**：默认选中“跳过，稍后在「系统设置 → 模型管理」里添加”。
     也可以选“本机 Ollama”（默认 `http://localhost:11434`、`qwen2.5:7b`）或
     “云端 API Key（OpenAI 兼容，如 DeepSeek）”（默认 `https://api.deepseek.com/v1`、
     `deepseek-chat`）。API Key 用 AES-256-GCM 加密后写入 `data\model_registry.sqlite3`，
     前端与日志只看到脱敏值。这一页还可以改**服务端口**（默认 `8080`）。
   - **第 4 步 · 完成前请确认**：核对数据目录、账号、端口与模型；无误点 **完成并自检**。
   - **第 5 步 · 自检结果**：显示四项自检结果；全部通过后点 **进入控制台**（有失败项可按提示点「重新检测全部四项」）。
3. 点第 4 页 **完成并自检**、第 5 页 **进入控制台**：向导窗口关闭、服务继续启动，控制台在原生窗口
   （WebView2）中打开登录页 `http://127.0.0.1:8080`；用刚建的账号登录，进入「总览」。网页模式才用 `--web` 开浏览器。
   端口默认 `8080`：首启向导里可以换端口；日常启动如果端口被占，会告诉你占用原因并给出处理办法（见第二节）。
4. **首次设置不发恢复码**：登录后建议马上到左侧 **恢复码** 页生成一枚并保存。

> **点「取消」或直接关窗会怎样？** 在第 1～4 步取消/关窗＝放弃本次设置：不创建账号，也不会启动控制台；
> 重新双击桌面图标可再次进入向导。已经点过 **完成并自检** 后再关窗不会丢设置，服务照常启动，只是不会自动弹出控制台窗口。

地址以实际打开的控制台为准（桌面端是原生窗口；网页端＝浏览器访问，用 `--web` 启动或直接打开地址）。
`<数据目录>\config\current_url.txt` 只是启动器 `scripts/start_liuhao.py` 在某次启动时写下的快照
（安装版 `LiuHao.bat` 启动会写；双击桌面图标启动不写；源码 `start-liuhao.bat` 默认也不写），
可能是旧端口/死 pid，**不要以它为准**。

> 界面文字以当前版本 0.2.0 的代码为准；如果你看到的按钮/提示与此处不同，请截图反馈。

> 已经配置过的机器再次启动会跳过「鎏灏首次设置」，十几秒进入控制台。

## 二、日常使用

- **启动**：双击快捷方式 → 状态窗口 + 托盘图标常驻。关掉状态窗口只是隐藏到托盘，网关继续运行；要真正退出用托盘菜单“退出”。
- **登录**：控制台窗口打开后输入「鎏灏首次设置」里创建的管理员账号密码。
- **聊天**：控制台左侧 **自由对话 → 直接对话** → 输入消息。回复来自你在首次设置或
  模型管理里配置的 Provider；未配置模型时聊天会明确报错，不会伪造回复。
- **模型管理**：控制台「系统设置 → 模型管理」（**系统设置** 仅根账号可见）可新增、编辑、测试连接、切换默认模型。
  支持 OpenAI、DeepSeek、月之暗面 Kimi、Anthropic、Google Gemini、本地 Ollama，
  以及“OpenAI 兼容”自定义端点；模型名可自己填，不是白名单。
  **新模型必须先点「测试连接」通过，才能勾选「设为默认模型」**；没通过的可以保存，但设置默认会被拒绝。
  保存后**下一条消息立即生效，无需重启**。
- **停止**：托盘菜单「停止服务（仅停网关，托盘保留）」只停网关、托盘保留；要结束整个程序用托盘菜单「退出（停止网关并关闭托盘）」（状态窗口里的同名按钮等效）。需要命令行模式排障时，在程序目录运行 `LiuHao.bat --console`。

端口默认 `8080`（0.1.1+）。**首启向导里可以换端口；日常启动如果端口被占，会告诉你占用原因并给出处理办法**：

1. **先看原因**：窗口最后几行会写“网关端口 8080 已被占用（占用者：PID … 程序名）”。
2. **关掉占用程序再试**：关掉占用 8080 的程序（或重启电脑）后重新启动。
3. **换端口**：首启向导里可以换；已完成首启的机器在启动入口填一个空闲端口（例如 8081）后重新启动，不用改快捷方式；
   地址随之变成 `http://127.0.0.1:8081`。
4. 纯命令行 / 无桌面时不会弹窗，而是逐行打印「处理一／处理二」：复制「处理二」下面那条
   命令（含引号）重跑即可（命令里已给出候选端口，通常是 8081）；**返回码 2 表示没有启动**。
   源码 / 命令行也可直接 `--api-port 8081`；地址以状态窗口里的「控制台：」为准。

## 三、数据在哪、怎么备份

全部用户数据默认在 `D:\LiuHaoData`（没有检测到可用非系统盘时，数据目录和备份目录都
自动落到 `%LOCALAPPDATA%\LiuHao`，安装继续、不会中断，向导会提示「没有检测到非系统盘，
数据与备份都在 C 盘，建议预留空间」；也可以改选非系统盘目录。实际位置见程序目录 `data-dir.txt`）：

| 文件/目录 | 内容 |
| --- | --- |
| `config\human_identities.json` | 账号与角色 |
| `config\auth_secrets.json` | 登录凭据哈希 |
| `config\app.env` | JWT/会话密钥（首次生成，重启复用） |
| `config\integrity.key` | 身份注册表完整性签名密钥 |
| `data\model_registry.sqlite3` | Provider 与加密后的 API Key |
| `data\model_config.key` | 模型配置解密密钥 |
| `conversation_store.db` | 对话历史 |
| `audit_store.db` | 审计证据链 |
| `workspace\` | 员工、目标、项目、文件 |

实际访问地址看状态窗口里的 **「控制台：」**。启动器还会在 `<数据目录>\config\current_url.txt` 写下
`url=` / `port=` / `pid=` 快照（安装版 `LiuHao.bat` 启动会写、双击桌面图标不写），但它可能过期，不要以它为准。
日志在 `<数据目录>\logs\`：`launcher.log`（启动器与向导）、`liuhao.log`（服务本身）。

备份：退出应用后，整体复制整个数据目录（默认 `D:\LiuHaoData`）即可；恢复时覆盖回同一路径。
注意 `model_config.key` 与 `model_registry.sqlite3` 必须一起备份，缺一个则
API Key 无法解密。

## 四、卸载

设置 → 应用 → LiuHao AI OS · 鎏灏智能中枢 → 卸载。

**程序和数据是分开的，卸载默认保留数据（0.1.1+）。**

- 默认**只删程序**，数据目录完整保留，重装后账号/会话/模型配置仍在。
- 需要彻底清理时，卸载器会先问一次「是否同时删除你的数据」（默认否），
  选择「是」后再问一次，两次确认才删除，无法恢复。

## 五、升级

升级方式有两种：**系统设置 → 软件更新 → 检查更新**（配置了更新源时），或**先退出鎏灏（托盘菜单「退出（停止网关并关闭托盘）」）→ 运行新版本安装包覆盖安装**。

- `系统设置` 里有「**软件更新**」卡片；未配置更新源时「检查更新」按钮为禁用并写明原因，不会假装“已是最新”。
- 安装到同一目录即可覆盖，数据目录不受影响；放在 D 盘的账号、Key、聊天记录都会保留。
- 安装完成后必须**关闭并重新启动**鎏灏，新版本才会生效。
- 安装前建议先复制一份数据目录（默认 `D:\LiuHaoData`）。
- 需要回滚时，直接运行上一版本安装包覆盖安装；回滚细节见 [faq.md](faq.md) 第 4 节。

## 六、常见问题

**Windows 提示「未知发布者」**
当前安装包使用**项目自签名证书**（主体 `CN=鎏灏智能中枢`），不是公开权威 CA，所以仍会提示「未知发布者」，属预期。点「更多信息 → 仍要运行」；也可先运行随包的「信任签名证书.cmd」。只从可信来源获取安装包并核对 SHA256。

**启动窗口一闪而过 / 起不来（0.1.1+）**

双击程序目录下的 `LiuHao.bat`（默认 `D:\LiuHao\LiuHao.bat`），窗口会停住并显示完整报错。
按三步排查：

1. 看窗口最后几行：`[FAIL]` 多为安装不完整或 `runtime\python.exe` 被杀软隔离，
   把程序目录加入白名单后覆盖安装；端口报错按下面“端口冲突”处理。
2. 看日志：`<数据目录>\logs\launcher.log`（启动器与向导）与
   `<数据目录>\logs\liuhao.log`（服务本身）。
3. 能打开界面时，用 **系统设置 → 遇到问题 → 一键诊断包 → 导出诊断包**，把生成的 zip 发给支持；
   打不开就把上面两个日志的最后 20～50 行发出来（不含密钥）。

**登录页进不去 / 忘记密码**

登录页点「忘记密码」，用恢复码重置；完整步骤见 [faq.md](faq.md) 第 5 节。
老账号没有恢复码时，同一页有「没有恢复码？在本机生成」入口；页面会直接显示新码
（只显示这一次），前提是用启动器自动打开的那个原生窗口，手动输入地址打开的页面不算本机证明。

**回复开头是 `[演示数据] 还没有配置模型…`（不是报错）**
说明当前没有可用的真实模型，系统没有伪造真实回答。回控制台「系统设置 → 模型管理」
添加真实模型、点「测试连接」通过后勾选「设为默认模型」，再回自由对话重新发一条。
Ollama 场景先确认 `ollama list` 能看到模型、且 Ollama 服务在跑。

**端口冲突（0.1.1+）**

程序默认使用 `8080`。**首启向导里可以换端口；日常启动如果端口被占，会告诉你占用原因并给出处理办法**：
先关掉占用程序再试，或在启动入口填一个空闲端口（例如 8081）后重新启动，不用改快捷方式；
源码 / 命令行启动用 `--api-port 8081`。

**浏览器显示旧界面或白屏（0.1.1+）**

1. 先确认托盘图标还在、状态窗口显示“运行中”。
2. 按 `Ctrl + F5`（或 `Ctrl + Shift + R`）强刷。
3. 按 `F12` → **Application（应用）** → **Service Workers** → 在
   `http://127.0.0.1:8080` 那一行点 **Unregister（注销）** → 重新打开地址。
4. 还不行：**Application（应用）** → **Storage（存储）** → **Clear site data（清除站点数据）** → 刷新。
   清站点数据会要求重新登录；账号、Key、聊天记录不受影响。
5. 换过端口时，旧标签页仍指向旧端口；以状态窗口「控制台：」里的新地址打开。

**占用空间**
程序装完（0.1.1 实测）约 10,855 个文件 / 150.9 MB，安装包约 30 MB；0.2.0 的文件数与体积以出包记录为准，不在文档里写死。另有数据目录（对话/审计随使用增长）。
不含任何模型；Ollama 模型单独占约 2GB 以上。

## 七、本轮验证与仍未验证的部分

- 安装后的开机自启（托盘）：**默认关闭**，需运行 `python -m src.desktop autostart enable` 才开启。
  开启后的注册表登记**已验证**：注册表值指向安装目录内的
  `runtime\pythonw.exe` 与 `scripts\liuhao_desktop.py`，托盘窗口能创建；
  文件缺失时会拒绝写入并给出原因，不会写一个注定失败的登记项。
- 0.1.0 交付包（34,731,647 字节，SHA256 `01BE18BB…64DA2`）：**已实跑安装冒烟**
  ——静默安装到临时目录、启动服务、取得控制台首页、注册并登录、接入本机
  Ollama，`POST /v1/chat` 拿到真实回复，再静默卸载；未点击渲染后的前端表单
  （登录/发消息走的是同一套 HTTP API，前端视觉冻结后再补一次 UI 点击回归）。
- 卸载器：静默卸载已验证——程序目录、桌面/开始菜单快捷方式、卸载注册表项移除，
  `data-dir.txt` 记录的数据目录原样保留；交互式「是否删除数据」的“删除”分支
  已单独实测（连续两次确认后按实际数据目录删除）。
- 真实模型回复（本机）：本轮冒烟用本机 Ollama `qwen2.5:3b` 实测——模型连通性探测通过
  （约 1.36 秒），`POST /v1/chat` 11.2 秒返回真实生成文本。
- **填 Key 即用（安装版单进程）**：另起一份临时安装，只启动一次后端，通过控制台
  设置页同一组接口保存 DeepSeek Key（0.047 秒），不重启直接发消息，1.39 秒拿到
  真实回复；同一 PID 全程存活。保存/列表/聊天响应、服务日志与数据目录均未出现
  明文 Key（扫描命中 0），列表只显示 `sk-b…b47c` 脱敏串；故意写错一位 Key 返回
  `invalid_key` 与中文提示，无异常栈。未点击渲染后的表单，走的是设置页同一套 HTTP 接口。
- 升级：发布清单的生成与读取**已验证**（`up_to_date` / `update_available` /
  `invalid_manifest` 三种结果都实测过）；「下载 → 校验 → 备份 → 应用 → 回滚」
  未在安装版上实跑。
- 代码签名：**项目自签名**（主体 `CN=鎏灏智能中枢`），不是公开权威 CA；未导入信任的机器会提示「未知发布者」，运行随包「信任签名证书.cmd」后签名状态应为「有效」。
