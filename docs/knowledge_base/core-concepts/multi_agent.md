# 多智能体协作

单个智能体的能力是有限的。LiuHao AI OS 支持多智能体协作，让多个专业智能体像团队一样协同工作，完成更复杂的任务。

---

## 为什么需要多智能体

### 单个智能体的局限

1. **专业深度有限**：一个智能体难以精通所有领域
2. **注意力有限**：复杂任务容易丢失上下文
3. **视角单一**：缺少多角度审视和纠错
4. **效率瓶颈**：串行处理，难以并行加速

### 多智能体的优势

1. **专业分工**：每个智能体专注特定领域，深度更高
2. **并行执行**：独立任务可以同时进行，提升效率
3. **多角度审视**：不同智能体从不同视角检查，减少错误
4. **鲁棒性**：单个智能体失败不影响整体
5. **可扩展性**：根据任务动态增减智能体

## 智能体角色与专业化

多智能体系统中，每个智能体有明确的角色定位和专业领域。

### 常见角色配置

| 角色 | 职责 | 典型能力 |
|------|------|---------|
| **协调者** (Coordinator) | 任务分配、进度跟踪、冲突调解 | 全局视野、决策能力 |
| **研究员** (Researcher) | 信息收集、资料整理、事实核查 | 搜索、阅读、总结 |
| **分析师** (Analyst) | 数据分析、模式识别、洞察提取 | 统计、建模、可视化 |
| **创作者** (Creator) | 内容生成、方案设计、创意输出 | 写作、设计、编程 |
| **评论员** (Critic) | 质量评估、问题发现、改进建议 | 审查、测试、批判思维 |
| **执行者** (Executor) | 具体操作、工具调用、任务落地 | 执行工具、API调用 |
| **记忆管理员** (Librarian) | 知识管理、信息检索、档案维护 | 记忆系统、知识库 |

### 专业化的实现

```python
# 创建专业化智能体团队
team = client.agents.create_team(
    name="产品研发团队",
    agents=[
        {
            "role": "manager",
            "name": "项目经理",
            "specialization": "项目管理、进度协调"
        },
        {
            "role": "researcher",
            "name": "市场研究员",
            "specialization": "市场分析、用户研究"
        },
        {
            "role": "creator",
            "name": "产品设计师",
            "specialization": "产品设计、原型制作"
        },
        {
            "role": "critic",
            "name": "质量审核员",
            "specialization": "质量检查、用户体验评估"
        }
    ]
)
```

## 通信模式

智能体之间通过多种方式进行通信和协作。

### 1. 消息传递（Message Passing）

智能体之间直接发送消息：

```
智能体A ──消息──→ 智能体B
```

**特点**：
- 点对点通信
- 异步或同步
- 适合定向请求和响应

```python
# 智能体间消息传递
client.agents.send_message(
    from_agent="agent-researcher",
    to_agent="agent-analyst",
    subject="数据分析请求",
    content="请分析以下销售数据...",
    attachments=["sales_data.csv"]
)
```

### 2. 发布/订阅（Publish/Subscribe）

通过事件总线进行松耦合通信：

```
发布者 ──事件──→ 事件总线 ──事件──→ 订阅者1
                            └───→ 订阅者2
                            └───→ 订阅者3
```

**特点**：
- 一对多通信
- 发布者和订阅者解耦
- 适合事件驱动的场景

### 3. 共享内存（Shared Memory）

通过共享的记忆空间交换信息：

```
智能体A ──写入──→ 共享记忆 ──读取──→ 智能体B
```

**特点**：
- 隐式通信
- 适合传递大量数据
- 需要同步机制

### 4. 黑板模式（Blackboard Pattern）

多个智能体在一个共享的"黑板"上读写信息：

```
         ┌─────────────┐
         │   黑板       │
         │ (共享工作区)  │
         └─────────────┘
          ▲    ▲    ▲
          │    │    │
      智能体A 智能体B 智能体C
```

详见 [黑板模式](#黑板模式) 章节。

## 协作模式

LiuHao AI OS 支持多种多智能体协作模式。

### 模式一：主从模式（Master-Slave）

一个主控智能体分配任务，多个从属智能体执行。

```
        ┌─────────┐
        │  主控   │
        └────┬────┘
       ┌─────┼─────┐
       ▼     ▼     ▼
    从属A  从属B  从属C
```

**适用场景**：
- 任务可以明确分解为独立子任务
- 需要统一协调和结果汇总
- 有明确的决策者

**工作流程**：
1. 主控智能体接收目标
2. 主控分解任务，分配给从属智能体
3. 从属智能体并行执行
4. 从属返回结果给主控
5. 主控汇总并输出最终结果

**示例**：研究报告生成
- 主控：协调者，负责分配研究方向和汇总
- 从1：市场研究员，收集市场数据
- 从2：技术研究员，收集技术资料
- 从3：竞品研究员，分析竞品信息

### 模式二：流水线模式（Pipeline）

智能体按顺序排列，每个智能体处理后传递给下一个。

```
智能体A → 智能体B → 智能体C → 输出
```

**适用场景**：
- 任务有明确的阶段划分
- 每个阶段有专业的智能体负责
- 数据流清晰，单向流动

**工作流程**：
1. 数据进入第一个智能体
2. 每个智能体完成自己的处理
3. 结果传递给下一个智能体
4. 最后一个智能体输出最终结果

**示例**：内容生产流水线
- 智能体A：资料收集与整理
- 智能体B：初稿撰写
- 智能体C：编辑润色
- 智能体D：质量审核
- 智能体E：排版发布

### 模式三：委员会模式（Committee）

多个同级智能体共同决策，通过投票或协商达成共识。

```
      智能体A  智能体B  智能体C
         \      |      /
          \     |     /
           ▼    ▼    ▼
         ┌─────────────┐
         │   决策模块    │
         └──────┬──────┘
                ▼
            最终决策
```

**适用场景**：
- 高风险决策，需要多方验证
- 需要多角度审视的问题
- 没有单一"正确答案"的场景

**决策机制**：
1. **多数投票**：超过半数同意即通过
2. **一致同意**：全部同意才通过
3. **加权投票**：根据专业权重投票
4. **辩论协商**：智能体间辩论直到达成共识

**示例**：投资决策委员会
- 智能体A：基本面分析师
- 智能体B：技术面分析师
- 智能体C：风险评估师
- 决策：三个智能体都给出建议，综合后决策

### 模式四：黑板模式（Blackboard Pattern）

多个智能体共享一个"黑板"（共享工作区），各自读取和写入信息，共同推进问题解决。

详见 [黑板模式](#黑板模式) 章节。

### 模式选择指南

| 模式 | 适合任务类型 | 优点 | 缺点 |
|------|------------|------|------|
| 主从模式 | 可分解的任务 | 控制简单、高效 | 主控单点瓶颈 |
| 流水线 | 分阶段处理 | 专业化程度高 | 灵活性差 |
| 委员会 | 重要决策 | 质量高、多角度 | 速度慢、成本高 |
| 黑板模式 | 开放式问题 | 灵活、涌现性 | 协调复杂 |

## 冲突解决

多智能体协作中不可避免会出现冲突，需要有效的解决机制。

### 冲突类型

1. **目标冲突**：智能体追求的目标不一致
2. **资源冲突**：多个智能体竞争同一资源
3. **意见冲突**：对同一问题有不同判断
4. **行动冲突**：智能体的行动相互干扰

### 解决策略

#### 1. 层级裁决

按智能体的权限层级解决：

```
低层级冲突 → 同层级协商 → 上级裁决 → 最高级（人类）
```

#### 2. 投票表决

多个智能体投票决定，适用于委员会模式：

```python
result = committee.vote(
    question="是否采纳方案A？",
    options=["同意", "反对", "弃权"],
    mechanism="majority"  # majority / unanimous / weighted
)
```

#### 3. 拍卖机制

资源分配冲突时使用拍卖：

```python
# 资源拍卖示例
winner = auction.allocate(
    resource="gpu_instance_1",
    bidders=["agent_a", "agent_b", "agent_c"],
    strategy="highest_priority"
)
```

#### 4. 协商对话

智能体通过对话协商解决分歧：

```
智能体A: 我认为应该先做市场调研
智能体B: 但技术可行性还不明确，应该先做技术验证
智能体A: 这样吧，我们并行进行，每周同步进度
智能体B: 好的，就这么定了
```

#### 5. 人类介入

当冲突无法自动解决时，升级到人类决策者：

```python
# 冲突升级
if conflict.cannot_resolve() and conflict.impact > THRESHOLD:
    conflict.escalate_to_human(
        reason="智能体间对方案选择存在重大分歧",
        deadline="2026-10-10 18:00"
    )
```

## 黑板模式详解

黑板模式是 LiuHao AI OS 中一种重要的协作模式，特别适合解决复杂的、开放式的问题。

### 核心思想

```
         ┌─────────────────────────┐
         │        黑 板             │
         │  (共享的问题状态空间)      │
         │  - 问题描述               │
         │  - 中间结果               │
         │  - 假设                   │
         │  - 解决方案片段           │
         └───────────┬─────────────┘
                     │
         ┌───────────┼───────────┐
         ▼           ▼           ▼
    ┌───────┐   ┌───────┐   ┌───────┐
    │专家A  │   │专家B  │   │专家C  │
    │(知识源)│   │(知识源)│   │(知识源)│
    └───────┘   └───────┘   └───────┘
```

### 工作原理

1. **初始状态**：问题被写入黑板
2. **机会主义执行**：每个专家智能体观察黑板，发现自己能贡献的部分就行动
3. **增量式构建**：解决方案逐步在黑板上构建
4. **终止条件**：当问题被解决或达到终止条件时停止

### 黑板内容层级

黑板通常分为多个层级，从抽象到具体：

```
Level 0: 问题定义（目标、约束）
Level 1: 整体方案（策略、框架）
Level 2: 子问题分解
Level 3: 具体解决方案片段
Level 4: 最终答案
```

### 知识源（智能体）

每个知识源智能体：
- 有特定的专业领域
- 有自己的触发条件（黑板上出现什么信息时行动）
- 行动后更新黑板状态

```python
# 伪代码：知识源定义
class KnowledgeSource:
    name: str
    specialty: str
    
    def can_contribute(self, blackboard_state) -> bool:
        """判断当前黑板状态下自己能否贡献"""
        pass
    
    def contribute(self, blackboard_state) -> BlackboardUpdate:
        """执行贡献，更新黑板"""
        pass
```

### 适用场景

- 问题定义不明确，需要逐步探索
- 解决方案需要多个专业领域的知识
- 问题解决过程是涌现性的，无法预先规划完整路径
