# 规划引擎概念

规划引擎是 LiuHao AI OS 智能体的核心能力之一，负责将抽象目标分解为可执行的具体步骤。本文介绍规划引擎的工作原理、核心策略和关键概念。

---

## 什么是规划

规划（Planning）是智能体从当前状态出发，寻找一条到达目标状态的行动路径的过程。

在 LiuHao AI OS 中，规划引擎处理：

- **目标理解**：解析用户意图，明确目标和约束
- **任务分解**：将大目标拆分为可执行的子任务
- **路径选择**：在多种可能的执行路径中选择最优方案
- **动态调整**：根据执行反馈实时调整计划

---

## 目标分解

目标分解是规划的第一步，将复杂的高层目标拆解为可管理的子任务。

### 分解策略

#### 1. 按时间顺序分解

将任务按执行的先后顺序拆分：

```
目标：完成项目报告
├── 步骤1：收集数据
├── 步骤2：分析数据
├── 步骤3：撰写初稿
├── 步骤4：审校修改
└── 步骤5：最终交付
```

#### 2. 按子目标分解

将大目标分解为多个独立的子目标：

```
目标：搭建一个网站
├── 子目标A：前端页面开发
│   ├── 首页设计
│   ├── 产品页面
│   └── 联系页面
├── 子目标B：后端API开发
│   ├── 用户认证
│   ├── 数据接口
│   └── 管理后台
└── 子目标C：部署上线
    ├── 服务器配置
    ├── 域名解析
    └── SSL证书
```

#### 3. 按抽象层次分解（递归分解）

从高层抽象逐步细化到具体操作：

```
Level 0: 优化网站性能
Level 1: 前端优化 / 后端优化 / 数据库优化
Level 2: 图片压缩 / 代码分割 / 缓存策略 / SQL优化...
Level 3: 使用WebP格式 / 配置CDN / 添加索引...
```

### 任务图（Task Graph）

分解后的任务形成有向无环图（DAG），表示任务间的依赖关系：

```
任务A ──→ 任务B ──→ 任务D
   │              ↗
   └──→ 任务C ──┘
```

- 任务 B 和 C 可以并行执行
- 任务 D 依赖 B 和 C 的完成

## 多策略规划

LiuHao AI OS 的规划引擎支持多种规划策略，并能根据任务特点自动选择或组合使用。

### 策略一：LLM 提示规划（LLM Prompt Planning）

利用大语言模型的推理能力生成计划。

**适用场景**：开放式任务、创意性任务、没有明确模板的场景

**工作方式**：
1. 将目标、上下文和约束输入 LLM
2. LLM 生成初步计划
3. 验证计划的可行性
4. 迭代优化

```python
# 伪代码示例
plan = llm_planner.plan(
    goal="分析销售数据并生成报告",
    context={"time_range": "2026年Q3"},
    constraints={"max_steps": 10, "output_format": "markdown"}
)
```

### 策略二：模板匹配规划（Template-based Planning）

从预定义的计划模板库中匹配最适合的方案。

**适用场景**：重复性任务、标准化流程、已知模式的任务

**模板示例**：

```yaml
template: research_report
description: 研究报告生成模板
steps:
  - id: gather_info
    name: 信息收集
    tool: web_search
  - id: organize_info
    name: 信息整理
    tool: text_analyzer
  - id: draft_report
    name: 撰写报告
    tool: text_generator
  - id: review_report
    name: 审校报告
    tool: critic_agent
```

### 策略三：搜索式规划（Search-based Planning）

在状态空间中搜索最优路径。

**适用场景**：有明确状态定义、可以评估中间状态的任务

**常用算法**：
- BFS / DFS
- A* 搜索
- 蒙特卡洛树搜索（MCTS）

### 策略四：混合规划（Hybrid Planning）

结合多种策略的优势。

**典型流程**：
1. 先用 LLM 生成初步计划（快速、灵活）
2. 用搜索算法优化具体步骤（精确、最优）
3. 用模板填充标准化环节（可靠、高效）

### 策略选择器

规划引擎根据任务特征自动选择策略：

| 任务特征 | 推荐策略 |
|---------|---------|
| 开放式、创造性 | LLM 规划 |
| 标准化、重复性 | 模板规划 |
| 状态明确、可度量 | 搜索规划 |
| 复杂、多阶段 | 混合规划 |

## 计划验证

生成的计划需要经过验证才能执行，确保计划的可行性和正确性。

### 验证维度

#### 1. 可行性验证

- 所需工具是否可用
- 资源是否充足（时间、token、计算资源）
- 权限是否满足

#### 2. 完整性验证

- 是否覆盖了所有子目标
- 依赖关系是否完整
- 是否有明确的终止条件

#### 3. 一致性验证

- 步骤之间是否有矛盾
- 资源分配是否冲突
- 时间线是否合理

#### 4. 安全性验证

- 是否符合安全策略
- 是否有越权操作风险
- 是否符合合规要求

### 验证流程

```
生成计划
    │
    ▼
┌─────────────┐
│ 静态分析     │  检查语法、结构、依赖
└──────┬──────┘
       │通过
       ▼
┌─────────────┐
│ 模拟执行     │  沙箱中模拟关键步骤
└──────┬──────┘
       │通过
       ▼
┌─────────────┐
│ 策略审查     │  检查是否符合安全和合规策略
└──────┬──────┘
       │通过
       ▼
    批准执行
```

## 计划优化

初始计划往往不是最优的，优化阶段可以提升计划的质量和效率。

### 优化目标

1. **最小化步骤数**：用更少的步骤完成目标
2. **最小化成本**：减少 token 消耗、API 调用费用
3. **最小化时间**：缩短总执行时间
4. **最大化质量**：提高输出质量
5. **最大化可靠性**：降低失败风险

### 优化技术

#### 1. 步骤合并

将多个小步骤合并为一个更大的步骤，减少 overhead：

```
优化前：
  步骤1：读取文件A
  步骤2：读取文件B
  步骤3：合并内容

优化后：
  步骤1：读取并合并文件A和文件B
```

#### 2. 并行化

识别可并行执行的步骤，同时执行以节省时间：

```
优化前（串行）：总耗时 30s
  步骤A (10s) → 步骤B (10s) → 步骤C (10s)

优化后（并行）：总耗时 20s
  步骤A (10s) ──┐
  步骤B (10s) ──┴→ 步骤C (10s)
```

#### 3. 提前失败

将高风险步骤前置，尽早发现问题：

```
优化前：简单步骤 → 困难步骤
  问题：执行到一半才发现关键步骤不可行

优化后：困难步骤 → 简单步骤
  优势：早期发现问题，节省资源
```

#### 4. 缓存复用

检查是否有历史上成功的类似计划可以复用：

```python
# 检查计划记忆
similar_plans = plan_memory.search(goal="分析销售数据")
if similar_plans:
    # 复用并调整已有计划
    plan = adapt_plan(similar_plans[0], new_context)
else:
    # 生成新计划
    plan = generate_new_plan(goal)
```

## 计划记忆与复用

### 计划记忆

LiuHao AI OS 会记住成功（和失败）的计划，形成计划记忆库。

**存储内容**：
- 计划的目标和上下文
- 计划的步骤结构
- 执行结果（成功/失败、耗时、质量评分）
- 执行过程中的调整

### 计划复用

当新任务到达时，规划引擎会：

1. **检索**：在计划记忆中搜索类似的成功计划
2. **适配**：根据新任务的上下文调整计划
3. **验证**：验证调整后的计划是否可行
4. **执行**：执行并记录新的经验

### 计划演化

随着使用次数增加，计划会不断优化：

```
版本1：初次生成的计划
   ↓ 执行后反馈
版本2：根据经验调整的计划
   ↓ 多次执行优化
版本3：精炼后的高效计划
```

## 规划与执行的闭环

规划不是一次性的，而是与执行形成动态闭环：

### 执行中的规划调整

```
┌─────────┐
│  规划    │
└────┬────┘
     │
     ▼
┌─────────┐
│  执行    │
└────┬────┘
     │
     ▼
┌─────────┐
│  监控    │
└────┬────┘
     ├─ 正常 ─→ 继续执行
     │
     ├─ 偏差 ─→ 重规划 ─┐
     │                  │
     └─ 失败 ─→ 应急规划 ─┤
                        │
                        └──────→ 回到规划
```

### 触发重规划的条件

- 执行结果与预期偏差过大
- 发现了新的信息或约束
- 某个步骤失败且无法重试
- 用户提出了新的要求
- 资源状况发生重大变化
