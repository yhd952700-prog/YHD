# 架构总览

LiuHao AI OS（鎏灏 X）是一个人类主权自主智能体操作系统（Human-Sovereign Agent Operating System）。本文档从高层次介绍系统架构、设计原则和技术选型。

---

## 高层架构

### 系统架构图

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户界面层 (L-CORE)                       │
│  驾驶舱 · CLI · SDK · API Gateway · 第三方集成                    │
├─────────────────────────────────────────────────────────────────┤
│                      智能体运行时层 (Agent Runtime)              │
│  智能体工厂 · 专业智能体 · 智能体组织 · 智能体网络 · 协作引擎      │
├─────────────────────────────────────────────────────────────────┤
│                      内核层 (LiuHao Kernel)                     │
│  ┌──────────┬──────────┬──────────┐                              │
│  │ 智能内核  │ 代理内核  │ 主权内核  │  14 个内核                  │
│  │ (6个)    │ (5个)    │ (3个)    │                              │
│  └──────────┴──────────┴──────────┘                              │
├─────────────────────────────────────────────────────────────────┤
│                      基础设施层 (Infrastructure)                │
│  数据库 · 消息总线 · 缓存 · 对象存储 · 监控 · 日志               │
└─────────────────────────────────────────────────────────────────┘
```

### 分层说明

#### 第 1 层：用户界面层（L-CORE）

L-CORE 是人类与系统交互的主接口，提供多种接入方式：

- **驾驶舱（Console）**：Web 控制台，可视化管理和监控
- **CLI**：命令行工具，适合脚本和自动化
- **SDK**：多语言 SDK，支持应用集成
- **API Gateway**：RESTful API + WebSocket
- **第三方集成**：Slack、飞书、微信等平台对接

#### 第 2 层：智能体运行时层

负责智能体的创建、运行和协作：

- **智能体工厂**：根据配置创建不同类型的智能体
- **专业智能体**：预构建的领域专用智能体
- **智能体组织**：组织结构和角色管理
- **智能体网络**：智能体间通信和发现
- **协作引擎**：多智能体协作模式和协调

#### 第 3 层：内核层（LiuHao Kernel）

系统的核心，由 14 个内核组成，分为三大类：

- **智能内核（Intelligence Kernels）**：6 个，负责感知、记忆、推理等智能能力
- **代理内核（Agency Kernels）**：5 个，负责执行、资源、网络等代理能力
- **主权内核（Sovereignty Kernels）**：3 个，负责安全、审计、合规等主权能力

详见 [内核架构](kernels.md)。

#### 第 4 层：基础设施层

支撑系统运行的底层基础设施：

- **数据库**：PostgreSQL（主存储）、SQLite（轻量部署）
- **消息总线**：事件驱动架构的核心
- **缓存**：Redis 缓存层
- **对象存储**：文件和大对象存储
- **监控**：指标、日志、追踪
- **模型网关**：LLM 提供商路由和管理

## 14 个内核

LiuHao AI OS 的核心是 14 个内核，每个内核负责一组核心能力。

### 智能内核（Intelligence Kernels）— 6 个

| # | 内核 | 职责 |
|---|------|------|
| 1 | **identity** | 智能体身份、权限、L0-L7 作用域过滤 |
| 2 | **memory** | 多层记忆存储、作用域过滤、CRUD |
| 3 | **context** | 12 类输入 → 压缩 → 模型就绪上下文 |
| 4 | **capability** | 能力注册中心、版本、追溯链、作用域检查 |
| 5 | **policy** | ABAC 策略引擎、优先级评估、人类主权覆盖 |
| 6 | **execution** | Goal→Task→Plan→Action→Verify 全链路 |

### 代理内核（Agency Kernels）— 5 个

| # | 内核 | 职责 |
|---|------|------|
| 7 | **resource** | CPU/Mem/Storage/Token/Time/$ 六种配额 |
| 8 | **event** | 统一事件总线、correlation ID、死信重试 |
| 9 | **network** | 协议适配（A2A/MCP/gRPC/HTTP/WS）、路由 |
| 10 | **trust** | 信任评分、传播、衰减、撤销 |
| 11 | **evaluation** | 结果评估、反馈、重规划触发、升级 |

### 主权内核（Sovereignty Kernels）— 3 个

| # | 内核 | 职责 |
|---|------|------|
| 12 | **security** | RBAC+ABAC、Vault Transit 加密、审计 |
| 13 | **audit** | 审计链（hash-chain）、关联查询 |
| 14 | **plugin** | 插件注册、热加载、版本兼容、作用域激活 |

> **总计：14 个内核，约 6,400 行核心代码。**

## 设计原则

### 1. 人类主权（Human Sovereignty）

人类始终拥有最终决策权。AI 的所有行动都在人类授权和监督下进行，关键决策必须经过人类确认。

- 人类可以随时介入和接管
- 关键操作需要人类审批
- 人类可以撤销 AI 的任何决策
- 透明可解释，AI 的决策依据可追溯

### 2. 内核级安全（Kernel-Level Security）

安全不是附加功能，而是内核级的基础能力。每个操作都经过安全内核的检查。

- 零信任架构
- 最小权限原则
- 纵深防御
- 设计为不可篡改的审计日志（运行时完整性当前 UNVERIFIED）

### 3. 可观测性优先（Observability First）

系统的每个部分都应该是可观测的。你无法管理你无法测量的东西。

- 所有内核操作都有指标
- 完整的审计追踪
- 分布式追踪
- 实时监控和告警

### 4. 可演进性（Evolvability）

系统设计支持持续演进，不被当前的实现限制。

- 模块化设计，松耦合
- 接口驱动，易于替换
- 插件架构，可扩展
- 向后兼容，平滑升级

### 5. 诚实性（Honesty）

系统如实报告自身状态，不夸大能力。

- 状态如实标记（NOT VERIFIED 就是未验证）
- 不把"有代码"当"已实现"
- 不把"测试通过"当"生产已验证"
- 每个声明都要有证据

### 6. 简洁性（Simplicity）

在满足需求的前提下，尽可能简单。

- 避免过度设计
- 优先复用现有能力
- 减少概念数量
- 明确的边界和职责

## 关键架构决策

### 1. 内核架构 vs 单体架构

**决策**：采用微内核架构，将核心能力拆分为 14 个独立内核。

**理由**：
- 职责清晰，每个内核有明确的边界
- 可独立测试和演进
- 支持按需启用/禁用内核
- 安全性更好，内核间有明确的接口

### 2. 本地优先 vs 云端优先

**决策**：本地优先设计，同时支持云端模型。

**理由**：
- 数据隐私和安全
- 离线可用
- 成本可控
- 灵活切换模型提供商

### 3. SQL 优先 vs 向量优先

**决策**：SQL 优先，向量作为增强。

**理由**：
- 结构化数据用 SQL 更可靠
- 向量搜索用于语义检索
- 两者结合（混合搜索）效果最佳
- 降低运维复杂度

### 4. 事件驱动架构

**决策**：内核间通过事件总线通信，采用事件驱动架构。

**理由**：
- 松耦合，内核间不直接依赖
- 可观测性好，所有事件可追踪
- 易于扩展，新增内核不影响现有系统
- 支持异步和并行处理

## 系统边界

### LiuHao AI OS 负责什么

- 智能体的生命周期管理
- 记忆系统和知识管理
- 规划和推理引擎
- 工具调用和执行
- 多智能体协作
- 安全、审计和合规
- API 和 SDK 接口

### LiuHao AI OS 不负责什么

- 模型训练（只负责推理和微调）
- 底层基础设施管理（依赖云厂商或自托管）
- 特定业务逻辑（由应用层实现）
- UI/UX 设计（提供基础驾驶舱，可自定义）
